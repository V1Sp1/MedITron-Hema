Сценарии и предлагаемые роли

Роль определяется фактическими целями и действиями, а не названием стороны в договоре. Ниже предложения для проектирования; они требуют утверждения каждой организацией. Если поставщик сам использует данные для своей аналитики/обучения, его нельзя автоматически считать только обработчиком по поручению. Определения и поручение: статья 3 и статья 6 152-ФЗ.

Карточка каждой организации

  • Внутренний organizationId: [уникальный код]. Это технический идентификатор, не юридическое название.
  • Полное юридическое название: [название], ОГРН/ИНН: [реквизиты], адрес: [адрес].
  • Ответственный за обработку: [должность/ФИО], контакт субъекта: [адрес/email/телефон], контакт инцидентов: [канал].
  • Цели по отдельности: [подготовка исследовательского отчёта / медицинская услуга / поддержка]; текущий исследовательский выпуск не разрешает медицинскую цель.
  • Категории субъектов: [пациенты, представители, сотрудники]; отдельно категории данных каждого.
  • Основание по каждой цели: [конкретная норма/договор/форма согласия], доказательство: [номер, версия, дата, место хранения].
  • Роли клиники, лаборатории, платформы и хостинга: [согласованная схема].
  • Серверы/резервные копии/мониторинг/поддержка: [страна, адрес, исполнитель].
  • Разрешённые пользователи/группы: [перечень]; срок доступа и ответственный за отзыв: [правило].
  • Срок обработки каждой категории и порядок уничтожения: [ссылка на утверждённый документ].
  • Публикация политики и применимые уведомления: [ссылки/даты/обоснование исключения].
  • Медицинское назначение, классификация, регистрация при применимости: [заключения/реквизиты].
  • Дата/версия и утверждение руководителем: [подпись/дата].

Принцип разделения

В коде врач связан с одной организацией, ключ API — с одной организацией, медицинские объекты — с конкретным часовым браузерным сеансом и, для врачебной загрузки, конкретным врачом. Даже другой врач своей организации не получает доступ автоматически. Разделение обеспечивается проверками прикладного уровня; отдельные базы, MFA, сетевые границы и производственная аттестация пока не реализованы. Системный администратор компьютера имеет доступ к памяти/файлам: это доверенная роль, которую нужно ограничить организационно.

API выдаёт результат организации ключа и не сохраняет пациентские записи. Ответ содержит organizationId, stored=false, reportId=null. Эти поля не оформляют полномочия лаборатории на передачу исходных данных. Отчёт для реального пациента формировать в этом выпуске нельзя.
