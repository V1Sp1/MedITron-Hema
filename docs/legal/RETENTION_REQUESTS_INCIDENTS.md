# Сроки, обращения, удаление и инциденты

## Фактические сроки исследовательского выпуска

| Слой | Что находится | Срок и очистка |
|---|---|---|
| Браузерная форма/CSV/XLSX | Введённая или выбранная исследовательская строка, файлы в памяти страницы | Очистка; истечение часового сеанса; закрытие/перезагрузка страницы. Закрытие браузера само по себе не уведомляет сервер |
| Серверная SQLite :memory: | Наблюдения, проверенные входы, отчёты, оригинальные PDF как BLOB | До истечения 1 часа с подтверждения режима; чтение не продлевает. Недоступны сразу при истечении, фоновая уборка каждые 15 секунд, также при обращении. Очистка/выход/перезапуск удаляют |
| Временная папка hema-live-* | Загружаемый PDF, request/result worker, OCR и временный stderr | Удаление после успеха/ошибки; при штатной остановке. После аварии — при следующем старте/уборке только отмеченных папок завершённых процессов |
| Минимальные события в RAM | Действие, время, внутренний ID сеанса/объекта и результат | До 1 часа, максимум 2000 событий; не постоянный доказательный журнал согласий |
| auth.sqlite3 | Организации/контакты, врачебные логины/имена/хеши, API-хеши, сеансы, попытки входа | Учётные записи/ключи сохраняются. Сеанс врача до 8 часов; попытки до 15 минут с очисткой при обращении. Юридические сроки учётных данных определяет оператор |
| Старые hema.sqlite3/uploads | Возможные данные до исправлений | Новой программой не открываются. Сами не уничтожаются; не входят в новый ZIP. Требуют отдельного решения/удаления |
| Скачанные PDF/JSON, печать, копии пользователя | Экспортированный результат | Программа ими не управляет. Ответственность владельца копии, защита рабочего места и утверждённый срок |

Уменьшение числа копий не является гарантией физического стирания памяти, swap, SSD, резервных копий ОС или браузерных восстановлений. Для реального контура нужны управляемые рабочие места, шифрование, политика резервирования и проверяемая процедура уничтожения. Текущая часовая TTL — техническое ограничение прототипа, а не срок хранения медицинской документации клиники.

## Практическая очистка сейчас

Пользователь нажимает «Очистить»: frontend отправляет DELETE /api/privacy/session, сервер отзывает часовую cookie и удаляет принадлежащие ей объекты/PDF; browser сбрасывает форму. При ошибке запрос не выдаётся за успешный. Отдельно можно удалить report или observation через защищённый DELETE; observation каскадно удаляет связанные отчёты и исходный PDF. Чужой UUID не предоставляет полномочий.

Для исторических файлов администратор останавливает **все** экземпляры сервера с этим data-dir, изучает необходимость законного хранения и только затем выполняет:

```sh
.venv/bin/python -m backend.privacy_admin --data-dir data/local status
.venv/bin/python -m backend.privacy_admin --data-dir data/local purge-legacy
```

На Windows заменить интерпретатор на `.\.venv\Scripts\python.exe`. Команда purge просит напечатать DELETE LEGACY и удаляет только hema.sqlite3, его WAL/SHM и uploads. Не удаляет auth.sqlite3. Повторить для каждого исторического каталога. Проверить собственные бэкапы/экспорты отдельно. В этой работе такая необратимая команда на прежних пользовательских данных **не выполнялась**; сохранение источников не выдаётся за уничтожение.

## Регламент для будущего оператора

Назначить ответственного [должность/контакт] и заместителя. Реестр обращений: [защищённое место], поля: номер, дата, проверка полномочий, предмет, применимая норма/срок, действия, ответ, исполнители. Не запрашивать весь медицинский PDF для подтверждения личности по умолчанию. Не выдавать информацию по одному reportId; пациентская исследовательская cookie не заменяет установление личности в юридическом обращении.

При запросе доступа/уточнения/блокирования/удаления проверить полномочия, выявить все слои/обработчиков, определить законное действие и сроки, поручить исполнение, проверить результат, ответить и сохранить минимальное доказательство. При отзыве согласия проверить иные основания продолжения/обязательное хранение. При неизвестной сессии не раскрывать чужие записи для поиска. Порядок и сроки соотносятся с [статьёй 21 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/d3fe43a7c415353b17faab255bc0de92bea127da/).

## Инциденты

Признаки: чужой доступ, утечка ключа, ошибочная выдача отчёта, медицинские данные в логах/ZIP, потеря компьютера, компрометация зависимости. Сотрудник немедленно обращается по [канал]. Ответственный ограничивает доступ, отзывает ключ/сеанс, останавливает опасный маршрут, сохраняет необходимые доказательства с ограниченным доступом и устанавливает затронутых субъектов/системы. Не рассылает бланки по обычной почте для расследования.

Если установлены предусмотренные законом условия уведомления об инциденте, учитывать первоначальное уведомление уполномоченного органа в течение 24 часов и результаты внутреннего расследования в течение 72 часов; уточнить содержание и начало отсчёта по применимой норме. Эти сроки не заменять внутренним обещанием «разберёмся за неделю». Договорный срок сообщения от обработчика оператору должен оставлять время на исполнение. [Статья 21 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/d3fe43a7c415353b17faab255bc0de92bea127da/).

Провести учение на синтетическом инциденте: утечка тестового ключа → отзыв → 401; чужой UUID → 404; истечение → недоступность/очистка; архив → отсутствие runtime. Назначить частоту и сохранить результаты. Прототип не отправляет юридические уведомления автоматически.
