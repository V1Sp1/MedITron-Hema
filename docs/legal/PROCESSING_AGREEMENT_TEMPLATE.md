# Шаблон поручения обработки для API или поддержки

**Проект условий между оператором и обработчиком.** Заполнить после определения фактических ролей. Если лаборатория и клиника самостоятельно определяют разные цели, дополнительно оформить их взаимодействие; одного поручения платформе может быть недостаточно. Условия поручения и ответственность проверить по [статье 6 152-ФЗ](https://www.consultant.ru/document/cons_doc_LAW_61801/).

1. **Стороны.** Оператор: [полное название/адрес/реквизиты], обработчик: [название/адрес/реквизиты], представители и основание полномочий: [данные]. Ответственные/экстренные контакты: [каналы].
2. **Предмет и цель.** Обработчик выполняет [перечень операций] исключительно для [точная цель] по документированным указаниям оператора. Текущий исследовательский API не допускает реальные пациентские данные; до отдельного выпуска/допуска передаются только разрешённые исследовательские данные.
3. **Категории.** Субъекты: [перечень], данные: [точный минимальный перечень]. Идентификаторы/бланки передаются только при необходимости и основании. Модельный API принимает значения словаря, не ФИО, телефоны, номера карты или произвольный текст.
4. **Основание.** Оператор подтверждает и документирует основание, законность источника/передачи и информирование субъекта. Стороны распределяют обязанности по врачебной тайне, обращениям и применимым уведомлениям. Заявление в JSON не считается доказательством получения согласия пациента.
5. **Инфраструктура.** [Адреса серверов/РФ, доступ персонала, резервные копии, мониторинг, поддержка, каналы шифрования]. Любое изменение места/подрядчиков предварительно согласуется [порядок]. Указать, кто имеет административный доступ к памяти.
6. **Защита.** Утверждённые требования к конфиденциальности, доступу по полномочиям, журналам без медицинских значений, управлению уязвимостями, изоляции организаций, ключам и проверкам [приложение]. Оператор получает документы о мерах и возможность согласованной проверки. Не приравнивать внутренний ID организации к подтверждённой ИСПДн.
7. **Ключи.** Выдаются адресно, срок [срок], передача защищённым каналом [канал], владелец [должность], замена/отзыв [правило]. Ключи не попадают в URL, публичные примеры, браузер и журналы. При утечке немедленный отзыв и расследование. Текущая CLI сохраняет plaintext только в отдельный приватный файл, в базе хранится хеш.
8. **Запрет вторичного использования.** Запросы/ответы не используются для обучения, рекламы, объединения клиник или самостоятельного исследования без нового согласованного правомерного процесса. Ограничить телеметрию и отладочные дампы; поддержка использует синтетические примеры.
9. **Срок и уничтожение.** [Точные сроки по слоям], возврат/уничтожение по окончании поручения [процедура/подтверждение], резервные копии [правило]. Текущий лабораторный endpoint не сохраняет записи; лаборатория отвечает за собственную сохранённую/выданную копию.
10. **Обращения.** Обработчик не даёт неподтверждённому заявителю чужие сведения; передаёт запрос оператору по [канал] и выполняет согласованное поручение в [срок, позволяющий оператору соблюсти закон].
11. **Инциденты.** Уведомление оператора без неоправданной задержки, договорный предел [короткий срок], минимальные сведения, изоляция/отзыв ключей, расследование, сохранение необходимых доказательств без избыточных копий. Уведомления уполномоченных органов выполняет ответственная сторона в применимые сроки; договор их не отменяет.
12. **Медицинские границы.** Разрешённое назначение, версия модели/фраз, review результата, запрет самостоятельного клинического применения исследовательского выпуска и порядок допуска нового выпуска [приложение]. Обязанности лаборатории при выдаче отчёта реальному пациенту определить отдельно.
13. **Субподряд и ответственность.** [Перечень/предварительное согласование/обязанности/ответственность/аудит/расторжение]. Самостоятельные цели сторон выделить из поручения.

Приложения: схема потоков; перечень данных/операций; меры защиты; сроки; контакты; медицинское назначение; процедура обращений/инцидентов. Подписи/дата/версия: [поля].
