Начало

API для лабораторий: JSON и PDF

Версия от 2026-10-05. Реализован локальный исследовательский API: анализы → расчёт действующей сборкой baseline_v1 + отдельный ферритин v4 → файл отчёта. Числа и фразы совпадают с серверным расчётом сайта. API не предназначен для выдачи клинического заключения реальному пациенту. Внешний сервер пока не развёрнут.

Что работает

Базовый адрес локальной проверки: http://127.0.0.1:8000. Все методы требуют Authorization: Bearer …; ключ выдаётся лаборатории администратором и никогда не помещается в браузерный код, URL или тело запроса. Схема — /openapi.json, информация о возможностях и актуальной политике — GET /api/integration/v1/capabilities.

МетодНазначениеПрава ключа
GET /api/integration/v1/capabilitiesФорматы, политика, ограниченияЛюбой действующий ключ
POST /api/integration/v1/reportsСтруктурированные показатели → файлreports
POST /api/integration/v1/observations/pdfПакет PDF → черновик наблюденияpdf
GET /api/integration/v1/observations/{id}Прочитать свой черновикpdf
POST /api/integration/v1/observations/{id}/reportsПроверенный черновик → файлpdf и reports
DELETE /api/integration/v1/observations/{id}Удалить свой черновикpdf
POST /api/integration/predictПрежний расчёт только JSONpredict

audience: patient, doctor, both. format: pdf, json, zip; по умолчанию обе роли и ZIP. PDF содержит одну выбранную роль. ZIP содержит report-patient.pdf, report-doctor.pdf, reports.json (или только выбранную роль). JSON включает входные значения, вывод, ограничения, следующие действия, версии моделей/фраз/единиц и технический requestId. Числовые scores не являются проверенной вероятностью заболевания. В PDF пациента подробные scores не печатаются; роль отчёта не является отдельной границей авторизации для лаборатории.

requestId выдаётся сервисом; организация берётся из ключа. reportId:null, stored:false: отчёты не сохраняются на сервере и ссылки для последующего скачивания нет. Если требуется связать ответ с собственной записью, лаборатория ведёт соответствие запрос–ответ в своей системе, не передавая идентификаторы пациента этому прототипу. Такая связь с реальным пациентом сама по себе не делает данные обезличенными и не снимает текущий запрет клинического использования.

Создание доступа

Из корня проекта, только для вымышленной организации:

.venv/bin/python -m backend.integrations organization-create lab-demo --name "Вымышленная лаборатория" --contact "research@example.invalid"
.venv/bin/python -m backend.integrations key-create lab-demo --label "JSON и PDF, синтетическая проверка" --days 30 --scope reports --scope pdf --token-file /private/tmp/hema-lab-demo.key
.venv/bin/python -m backend.integrations key-list

Если сервер запущен с другим --data-dir, перед командой CLI указать тот же путь. Учётная база организаций и хешей ключей находится в его auth.sqlite3. Учётная запись врача для API не нужна: серверная интеграция использует собственный ключ организации. Без --scope выдаётся только прежнее право predict. Существующие ключи после миграции также остаются predict; расширение доступа выполняется выдачей нового ключа с нужными правами.

Ключ случайный, в базе только SHA-256; срок 1–90 дней, по умолчанию 30. Plaintext записывается один раз в новый приватный файл 0600, не печатается в консоли. Файл не перезаписывается. На Windows использовать .\.venv\Scripts\python.exe и приватный путь под личной папкой; ACL проверяется отдельно. Для сетевого развёртывания нужен секрет-хранилище. Отзыв: python -m backend.integrations key-revoke KEY_ID. Ротация: выдать новый, передать защищённым каналом, переключить клиента, отозвать старый. Отозванный ключ прекращает доступ к своим черновикам; новый ключ не наследует их, даже в той же организации. При утечке сначала отозвать ключ.

Структурированный JSON

Показатели передаются по словарю признаков и единиц; пропуски — null или отсутствующее поле, не нули. Обязательны возраст 18–120, пол F/M, Hb. Идентификаторы пациента, ФИО, даты рождения, произвольные текстовые поля, собственный verdict, organizationId и callback URL отвергаются.

{
  "policyVersion": "research-privacy-2026-10-04-v1",
  "dataKind": "synthetic",
  "researchOnly": true,
  "audience": "both",
  "format": "zip",
  "pregnancyStatus": "unknown",
  "inputs": {"age_years":42,"sex":"F","hemoglobin":108,"RBC":4,"MCV":78,"MCH":25,"RDW":17,"ferritin":9}
}

Для измеренного ферритина показывается результат анализа без прогноза. При его отсутствии v4 работает только в своей проверенной области; неизвестный статус беременности не считается отсутствием беременности. Конкретные ограничения — гибридная сборка. Мало данных → ограниченный вывод и список недостающих исследований; недоступная подключённая модель → 503, без подмены демо.

Готовый пример с полной вымышленной панелью — structured_request.json. Клиент laboratory_client.py требует httpx из .[integration] (в текущем окружении уже установлен):

.venv/bin/python scripts/laboratory_client.py --token-file /private/tmp/hema-lab-demo.key capabilities
.venv/bin/python scripts/laboratory_client.py --token-file /private/tmp/hema-lab-demo.key report --request examples/laboratory_api/structured_request.json --output /private/tmp/hema-new-reports.zip

Клиент проверяет TLS, отключает перенаправления и переменные окружения proxy, разрешает HTTP только на loopback, читает ключ из приватного файла и создаёт новый результат с правами 0600. Содержимое отчёта не печатается. Не задавайте verify=False. Для закрытого CA/mTLS предусмотрены --ca-file, --client-cert, --client-key; секретный ключ сертификата защищать отдельно. На Windows проверить ACL результата.

PDF: загрузка, проверка, расчёт

  1. Передать multipart с полями files (один или несколько PDF) и единственным metadata (JSON с policyVersion, dataKind, researchOnly, необязательными age_years, sex). Весь пакет одной загрузки образует одно наблюдение. Даты анализов могут отличаться.
  2. Получить observationId, revision, нормализованные inputs, найденные измерения, единицы, даты, предупреждения и requiresReview:true. Проверить исходный документ у себя: правильность распознавания, выбор повторных измерений, единицы, давность, пропуски. Неполные/неоднозначные/устаревшие значения не превращаются автоматически в подтверждённую норму.
  3. Передать исправленные inputs, исходную revision, тот же dataKind, опции отчёта и обязательное reviewedObservation:true в /observations/{id}/reports.
  4. Сохранить файл у себя; при желании сразу удалить черновик. Черновик исчезает максимум через 15 минут, по истечении ключа или при перезапуске. Чтение TTL не продлевает.
.venv/bin/python scripts/laboratory_client.py --token-file /private/tmp/hema-lab-demo.key upload-pdf --age 42 --sex F --output /private/tmp/hema-new-draft.json examples/full-demo/iron.pdf

Замените путь PDF на существующий синтетический бланк. Откройте и проверьте /private/tmp/hema-new-draft.json, исправьте inputs, затем:

.venv/bin/python scripts/laboratory_client.py --token-file /private/tmp/hema-lab-demo.key pdf-report --draft /private/tmp/hema-new-draft.json --reviewed --output /private/tmp/hema-new-pdf-reports.zip
.venv/bin/python scripts/laboratory_client.py --token-file /private/tmp/hema-lab-demo.key delete-draft OBSERVATION_UUID

--reviewed — явное подтверждение пользователя интеграции; сервер не способен доказать, что человек действительно сверил PDF. Клиент не подтверждает черновик автоматически. Имена файлов заменяются безопасными техническими именами. Исходники после обработки не сохраняются в Store; временные копии multipart/парсера удаляются при завершении. В Store только минимизированный черновик в RAM. Сбой ОС, swap, резервные копии, каталоги клиента и промежуточного шлюза требуют отдельной политики: удаление файла не означает гарантированное стирание носителя.

Ограничения и ошибки

JSON до 128 КиБ; PDF до 10 файлов, 20 МиБ каждый, 60 МиБ весь пакет, 100 страниц на файл. До 60 операций в минуту на ключ и 240 на процесс; учитываются также чтение/удаление/возможности. Одновременно распознаётся один пакет. Worker ограничен 180 секундами; клиент ждёт до 240. RAM Store общий, до 128 МиБ/1000 объектов. Сетевые/вычислительные ограничения не являются доказательством полной защиты от DoS.

КодДействие клиента
401Проверить ключ, срок, отзыв; не печатать его
403Выдать ключ с нужными правами
404Чужой/удалённый/истёкший черновик; загрузить свой заново
409Проверить revision и вид данных
413Уменьшить размер
422Исправить схему/данные/проверку PDF; сообщения не отражают содержимое
426Использовать внешний HTTPS через доверенный шлюз
429Соблюсти Retry-After
503/504Модель/генерация недоступна или распознавание не завершено
507Исчерпано временное хранилище; повторить после очистки

Ответы Cache-Control:no-store, nosniff; файл вложения имеет фиксированное имя, X-Hema-Request-Id для сопоставления. Автоматических callback/webhook и идемпотентного кеша нет. Повтор JSON не создаёт сохранённую медицинскую запись, но выполняет новый расчёт и выдаёт новый requestId. Ошибка/тайм-аут загрузки PDF может оставить черновик до TTL; не повторяйте запросы бесконтрольно.

Защита и границы готовности

Реализованы проверка scope и владельца на каждом методе, отдельная изоляция по организации и ключу, повторная проверка отзыва после расчёта/парсинга, запрет подмены владельца, ограничения тела/файлов/страниц/времени и закрытое временное хранение. События содержат только технические ID/операцию/время/результат; значения анализов, ключи и имена исходных файлов туда не записываются. Этот аудит ограничен RAM и теряется при перезапуске; для production нужен долговременный защищённый журнал с определённой политикой.

Значение dataKind:anonymized — заявление отправителя. Проверка найденных имени/даты рождения в PDF не доказывает полноценное обезличивание, особенно на сканах. Замена ФИО номером, который можно связать с человеком, не даёт автоматического разрешения на обработку. Пока допускаются только синтетические либо предварительно действительно обезличенные данные в исследовательском режиме.

Данные о здоровье относятся к специальным категориям ПД; применимое основание и исключения определяются отдельно по статье 10 152-ФЗ. Ключ/checkbox/обозначение «исследование» не заменяют правовое основание. Для работы с реальными клиентами остаются оператор и договорные роли лаборатории/сервиса, основания и порядок обработки, локализация и меры защиты, медицинская валидация и оценка применимости требований к медизделию; правовые заготовки не являются подписанными документами.

Для внешнего исследовательского доступа подготовлен пример Nginx (исходный файл отдельно): TLS 1.2/1.3, обязательный сертификат клиента плюс API-ключ, только namespace /api/integration/v1/, ограничение запросов/соединений, без проксирования браузерных методов. Конфигурация не применялась, сертификатов/домена нет, Nginx-тест и проверка сетевого развёртывания не выполнены. Backend остаётся на 127.0.0.1. Шлюз должен перезаписывать proxy-заголовки, а сервер доверять им только от loopback-шлюза. Не публикуйте dev-порты/папку data/рабочий ноутбук напрямую.

Перед production дополнительно нужны отдельное защищённое окружение, шифрование хранилищ/резервных копий, рабочий secret management, долговременный аудит и мониторинг, общие лимиты/очередь при нескольких процессах, изоляция PDF/OCR с минимальными правами и проверка вредоносных документов, управление зависимостями и независимая проверка безопасности. Текущий worker — ограниченный subprocess, не полноценная sandbox. Подготовленные меры следуют рекомендациям OWASP по файлам; источник также описывает дополнительные AV/CDR-меры. Настройка TLS/mTLS и буферизации опирается на документацию SSL Nginx и proxy.
