# Исправления безопасности и условия дальнейшего выпуска

Актуализация: 05.10.2026. Исходный аудит от 04.10.2026 сохранён в [08_SECURITY_LEGAL_AUDIT_RU.md](08_SECURITY_LEGAL_AUDIT_RU.md) и security_audit_evidence.json как исторический снимок. Настоящий документ описывает исправленную реализацию. Пользователь уточнил, что проект создаётся с нуля для нескольких клиник и лабораторного API; юридические основания реальных данных ещё не оформлены.

## Результат

Подготовлен ограниченный исследовательский выпуск. Закрыт открытый доступ по UUID, добавлены владельцы/сеансы/TTL/удаление, минимизация, ключи организаций, защита десериализации и более строгая упаковка. Сайт, модель, импорт и экспорт сохранены. Все новые запросы предназначены для синтетических или действительно обезличенных данных. Реальные идентифицируемые пациенты и клиническое использование не разрешены. Наличие галочки не превращает документ в обезличенный: система не является универсальным средством обнаружения персональных данных.

Полное соответствие законам и готовность клинического сервиса нельзя объявить достигнутыми: необходимы решения конкретных организаций, документы/договоры, защищённое развёртывание и медицинский допуск. Ниже каждое замечание связано с изменением и оставшимся условием.

## Новая архитектура доступа и данных

`frontend/src/privacy.js` показывает назначение, вид данных и отдельное подтверждение до чтения файлов/отправки. Server grant — криптографически случайная HttpOnly/SameSite=Strict cookie, сервер хранит её SHA-256 и минимальные параметры в RAM. UI-галочка не является медицинским согласием. Cookies Secure устанавливаются при HTTPS; текущий loopback HTTP не имитирует TLS.

`backend/privacy.py` формирует минимальный _access: grantId, doctorId при наличии, organizationId, dataKind, policyVersion, expiresAt. UUID — адрес записи; полномочия проверяются независимо. Другой сеанс получает 404, отсутствие врачебного входа — 401. Старый объект без владельца закрыт. Вход/выход врача отзывает прежний research-сеанс и его медзаписи. Внутри одной организации другой врач также не получает доступа автоматически.

`backend/store.py` создаёт только SQLite :memory: для medical payload/BLOB. Один процесс/worker сервера соответствует одному временному хранилищу. Перезапуск не восстанавливает медзаписи; auth.sqlite3 с учётными записями/хешами остаётся. Максимальная суммарная полезная нагрузка 128 МиБ и 1000 объектов, это не точный предел общей RAM Python/SQLite. Oversize даёт 507. Срок каждого объекта не позже истечения исходного часового grant. Background sweep каждые 15 секунд и очистка при доступе. Освобождение SQLite не является гарантией физического стирания памяти ОС.

PDF проходит приватную папку с generic filename; after normalize удаляется произвольный текст/identity metadata, затем исходный PDF перемещается в RAM BLOB, папка удаляется в finally. Worker/OCR temp находятся внутри неё. При аварии отмеченные папки dead PID очищаются при следующем старте/sweep. Папки живых параллельных экземпляров не удаляются. Проверки принадлежности/повторов делаются до минимизации; геометрия/значения/единицы/даты и issues остаются для сверки. CLI `lab_parser` по-прежнему умеет записывать полный исследовательский JSON: его нельзя использовать для обхода правил реальных данных.

При удалении observation удаляются оригинальные PDF и связанные reports. Очистка сеанса отзывает token и удаляет все его объекты; операция повторно проверяет живой grant перед сохранением результата, чтобы завершившийся parser не восстановил данные после отзыва. При удалении report исходный observation остаётся до своего удаления/TTL.

Короткий журнал в памяти: действие, время, внутренний sessionId/objectId, результат. Нет лабораторных значений, исходных строк, ФИО, паролей и токенов. Это диагностика research, а не доказательная система согласий/производственного аудита.

## Лабораторный API

Новая auth-модель сохраняет organizations и api_keys с hashed bearer-token, организацией, меткой, активностью и expiry. Выдача CLI в новый файл, отзыв по ID, TTL 1–90 дней. `POST /api/integration/predict` проверяет ключ, строгий исследовательский запрос, словарь/полноту и вызывает ту же модель. Ничего не записывает в Store; ответ маркирует stored=false/reportId=null. Organization берётся из ключа, не из тела. Название/контакт организации не заменяет договор оператора.

Пример и администрирование: [backend/INTEGRATIONS.md](../backend/INTEGRATIONS.md). 60 запросов/минуту на ключ и 240 суммарно на процесс; JSON до 128 КиБ. API не принимает идентификаторы пациентов, произвольные диагнозы и PDF. Нельзя использовать отсутствие постоянной базы как аргумент, что передачи/обработки персональных данных нет: законная модель определяется фактическими данными и действиями.

## Модель, ресурсы и зависимости

Joblib может выполнять код при десериализации. До load проверяются размер до 128 МиБ и SHA-256 точных байтов по backend/data/model_trust.json; загружаются те же байты через BytesIO. Незнакомые веса refused, status untrusted_weights, прогноз 503. Администратор может явно указать trusted-model-sha256 после собственной проверки; вычислить хеш незнакомого файла без проверки происхождения недостаточно. Registry/хеш — не цифровая подпись и не клиническое одобрение.

POSIX worker: CPU 120 секунд, файл 64 МиБ, число файловых дескрипторов 128, core dump запрещён; Linux дополнительно address space 1 ГиБ. Windows Job Object задаёт CPU, память процесса/группы 1 ГиБ, до 8 процессов и завершение группы; native execution на Windows здесь не проверено. На macOS нет надёжной установленной этим кодом жёсткой memory-квоты; внешний 180-секундный timeout, размер входа/выхода и последовательность пакетов остаются. Worker не является полноценным sandbox; для сетевого продукта нужна отдельная изоляция.

PyPI/pip-audit 2.10.1: 45 пакетов из установленного транзитивного runtime-графа (parser+server+model), 04.10.2026, известных уязвимостей не найдено. Детали в security_dependency_inventory.json, security_dependency_audit.json и security_runtime_requirements.txt. requirements-runtime.txt закрепляет снимок при установке как constraints. Это проверка известной базы на дату запроса, не доказательство отсутствия ошибок; изменения/другие платформы нужно проверять повторно. Vendored JS и фиксированные локальные шрифты сохраняются с лицензиями/хешами в манифесте; отсутствие опубликованных advisories на страницах [pdf-lib](https://github.com/Hopding/pdf-lib/security), [fontkit](https://github.com/Hopding/fontkit/security/advisories), [JSZip](https://github.com/Stuk/jszip/security/advisories) не равнозначно полноценному транзитивному npm-аудиту.

Интерпретатор испытаний — Python 3.12.14; [3.12.15 от 30.09.2026](https://www.python.org/downloads/release/python-31215/) содержит новые исправления безопасности. Launcher предупреждает при более старой patch-версии; промышленный выпуск требует актуального runtime/ОС. Ветка 3.12 теперь source-only, последний официальный installer 3.12.10 нельзя считать актуальным production runtime. Установка/миграция чужой управляемой среды этим исправлением не выполнялась.

## Проверки и передача

tests/test_security.py воспроизводит чужой ID/сеанс/клинику, очистку/TTL/каскад, identity minimization, обнаруженное ФИО в anonymized PDF, недопуск legacy, отзыв во время parser, api key hash/expiry/revoke/stateless, CSRF/размер/no-cache, memory bounds, отказ untrusted joblib **до load**, crash cleanup и отрицательные случаи упаковки. Они используют сгенерированные синтетические данные. Frontend privacy tests проверяют явный запрос/credentials/DELETE и видимость ошибки очистки. Итоговые проверки и факт браузерной проверки фиксируются в [07_VERIFICATION.md](07_VERIFICATION.md).

Новый архив включает исходники, технические пояснения, legal-шаблоны, выбранные веса v1/v2/v3 и отдельной biochemical_v4, отчёты внешней проверки, агрегированные метрики/графики, словари и разрешённые синтетические примеры. В рабочей сборке v1 + v4 только ферритин v4 добавлен отдельным биохимическим блоком; клинические case-головы не заменены. B12/PLP доступны лишь в исследовательском CLI. Контракт — docs/10_HYBRID_MODEL.md. Исключены все runtime roots, реальные/внешние построчные таблицы, splits/OOF-предсказания, произвольные загруженные документы, secrets и старые deliverables. Продуктовые требования PDF и редакционный DOCX сохранены как источники пояснений; они не являются пациентскими бланками. Обучающий CSV не переносится автоматически — для повторного обучения нужен отдельно правомерно полученный источник и явный --source. Отбор файлов не изменяет originals на рабочем компьютере.

Для команды использовать **Hema_project_2026-10-05_research_secure.zip**, а не старый ZIP от 04.10.2026. SHA-256 и FILES_MANIFEST позволяют проверить целостность; сами по себе они не удостоверяют автора. Открыть START_HERE.html → инструкция ОС → только синтетическая проверка. Правовой комплект: [legal/README.md](legal/README.md).
