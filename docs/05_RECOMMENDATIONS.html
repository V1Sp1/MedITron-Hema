Начало

Техническая реализация рекомендаций Hema

Рекомендации — версионированный детерминированный выбор готовых фраз. В обычном расчёте нет генерации текста LLM, облачного запроса, случайного выбора или назначений лекарств. Отдельные каталоги пациента и врача описывают тот же результат разным языком. Тексты и политика полноты имеют статус черновика и требуют медицинского согласования.

Файлы и версии

backend/data/recommendations_patient.json и recommendations_doctor.json содержат по 20 фраз, версия phrases-draft-1.2, clinicalReviewStatus=draft. backend/data/sufficiency_policy.json содержит coverage-draft-1.0, clinicalValidated=false. recommendations.py валидирует каталоги, вычисляет условия и группирует ответ. verdicts.py проверяет ModelVerdict; data_sufficiency.py определяет покрытие; model_service.py создаёт истинный вердикт.

Исходные клинические ориентиры сохранены в catalog.sources и backend/RECOMMENDATIONS.md. Это происхождение черновика, не доказательство медицинского утверждения или актуальности всех правил. Порог Hb берётся из кейса; версии каталогов не являются версиями обученных weights.

Структура каталога

Каталог имеет audience, version, clinicalReviewStatus, sources и items. У каждого item есть уникальный id, kind, topic, целочисленный priority, непустой text, when, suggestedFeatures, sourceIds. Разрешённые kind: conclusion, next_step, data_gap. Валидатор требует именно 20 фраз одной роли, известные условия/признаки/источники и не принимает произвольные выражения кода.

В text разрешена единственная подстановка {deficits}. Она заменяется контролируемыми русскими именами положительных дефицитов. Другие фигурные placeholders отклоняются. ID нужен для прослеживаемости и тестов; topic связывает смысл/причину, priority задаёт порядок. SuggestedFeatures — список недостающих полей для обсуждения, не автоматическое назначение обследования.

Вердикт и его происхождение

ModelVerdict содержит anemiaClass (один из 12 классов/null), deficits (уникальный список iron/B12/folate/B6/copper/null), inflammation (bool/null) и status evaluated/uncertain/out_of_scope. null списка означает «решения не переданы», пустой список — «положительных решений нет»: это разные состояния.

В обычном отчёте нужен modelConnected=true, непустой modelVersion и ModelVerdict. Scores, prediction.label и свободные предложения не создают решений. Истинный verdict строится адаптером из сохранённых моделей. В основном predict пользователь не может передать желаемый диагноз. Preview допускает явный verdict, но маркирует simulation=true/source=editorial_preview, не сохраняет отчёт и не объявляет настоящую модель подключённой.

verdict_context возвращает modelState и разрешённый для фраз контекст. Для specific model условий необходим state=evaluated. Возможные состояния: not_connected, missing_verdict, evaluated, uncertain, out_of_scope, inconsistent, suppressed_sparse. Если Hb, class, deficits или воспалительная цель противоречат друг другу, контекст не выдаёт конкретные дефициты для выбора специфических фраз. ReasonCodes помогают понять почему.

Значения conditions валидируются до исполнения; eval или произвольных Python-функций из JSON нет.

Полнота данных

Лабораторный счётчик учитывает только 35 лабораторных признаков, не возраст и пол. Required core: возраст, пол, Hb. CBC context: Hb/MCV/MCH. Группы покрываются так: iron — ferritin, B12 — vitamin_B12 либо active_B12, folate — folate, B6 — vitamin_B6, copper — copper. Наличие других полей группы отображается как контекст, но не обязательно заменяет initial alternative.

insufficient: нет core либо меньше 5 лабораторных значений. limited: минимум выполнен, но нет CBC context либо не покрыты iron/B12/folate. broader: есть core, минимум, CBC context и эти три группы. Broader не требует всех 35 анализов, не означает 100% уверенности и не измеряет качество модели. Покрытие B6/меди отображается отдельно.

Ответ содержит laboratoryCount/Total, availableFeatures/missingFeatures, missingEssential/missingCBCContext, groups, reasonCodes, summary, policyVersion, clinicalValidated=false и modelConfidence=null. Недостающий анализ не считается отрицательным результатом. Политика показывает ограничения доступных данных, не клинически обязательную панель.

Порядок выбора и ограничения количества

phrases_for_report проверяет inputs, вычисляет полноту и контекст verdict, загружает каталог роли. Items сортируются по priority по убыванию и затем по id. Для каждого выполняется _matches. Подстановка deficits использует список context. От suggestedFeatures удаляются уже имеющиеся поля. Если присутствует общий либо активный B12, оба стартовых B12-теста убираются из автоматических предложений: один не предлагается только потому, что отсутствует другой.

Результат включает до 3 conclusions, до 4 next_step items и до 4 data_gap items. Это три группы, а не 20 фраз одновременно. Data_gap добавляет причины недостатка данных; topic=model_limited дополнительно включает причины модельного ограничения. Warnings всегда содержит статус черновика.

Frontend показывает «Что удалось оценить», «Полнота данных/Недостаточно данных» и «Следующие шаги» отдельно. JSON/PDF/печать сохраняют ограничения вместе с выводом. Нет удаления предупреждения ради более определённого текста.

Пограничные примеры

Hb ровно 120 у F или 130 у M не ниже порога: анемия false, фразы должны использовать соответствующую формулировку. Normal Hb не исключает скрытые дефициты. Если есть положительный B12 при normal Hb и согласованный class, допустима фраза о дефиците без анемии. Если введён один Hb, specific cause-фразы подавляются, остаются Hb/общие шаги/ограничения.

iron_deficiency_anemia с Hb без анемии — конфликт; mixed_deficiency с явно одним компонентом — конфликт; anemia_other с положительным дефицитом — конфликт; latent_deficiency с явно пустым deficits — конфликт; inflammation=true без анемии — конфликт. Класс B6/copper сам по себе не определяет статус анемии. Сочетание iron+воспалительная цель при анемии допустимо как гипотеза, но совместное распознавание не валидировано данными кейса.

Когда вердикт uncertain, низкий maximum class score или sparse, специфические выводы не показываются. Нельзя переименовать неопределённость в отсутствие дефицита, назначить anemia_other по пропускам или вычислить вероятность mixed произведением scores.

Сохранение и изменение

При predict отчёт получает recommendationSnapshot. Обычный POST recommendations возвращает этот снимок, поэтому правка каталога не меняет прежние формулировки. Новые расчёты используют новую версию. Роли запроса и сохранённого отчёта должны совпасть, иначе 409.

При редактировании каталога меняйте обе роли осмысленно, повышайте version, сохраняйте draft до реального медицинского review, проверяйте уникальные IDs, 20 элементов, все условия/источники и корректность suggestedFeatures. Тестируйте матрицу 12 классов × обе роли, границы Hb, малые панели, противоречия и альтернативы B12. Обновляйте PROJECT_CONTEXT и описание. Не меняйте weights или пороги ради того, чтобы конкретная фраза чаще показывалась.

Дополнительный phrase file

--phrase-file поддерживает прежний формат: version, reviewed:true, items. Каждый item имеет уникальный id, text, audience patient/doctor/both и when, допускающий только anemia. Такой файл заменяет следующие шаги, но оставляет черновые conclusions, полноту и предупреждения основного каталога. Маркер reviewed:true — техническое условие, не доказательство клинического review. Пустой/неподтверждённый/невалидный файл приводит к 503 при получении рекомендаций. Обычный запуск не нуждается в этом override.

Правки медицинской команды — 2026-10-04

Источник — «Корректировка текста.docx»; неизменённая копия: data/reference/medical_text_corrections_2026-10-04.docx, SHA-256 в catalog.sources.medical_team. По порядку первых 12 тем документа обновлены 11 тем обеих ролей; у latent правок нет. Темы 13–20 и условия выбора сохранены. Добавленные списки исследований отражают редакционные предложения команды; не приписываются автоматически NICE/BSG/WHO. Статус draft сохранён: частичная редактура не подтверждает клиническую валидацию модели, правил покрытия и всех 40 фраз.

Интерпретации неоднозначностей:

  • «Креатин» трактован как креатинин (creatinine) по контексту eGFR; это предположение требует подтверждения команды.
  • Общий B12 указан приоритетно в пациентском тексте, активный — альтернативой. Уже введённый общий или активный B12 исключает предложение другого из suggestedFeatures. Оба не назначаются автоматически; NICE NG239 1.3.1 допускает один из них для начального исследования.
  • «Hb в норме / выше порога» заменено на «не ниже порога анемии»: равенство 120/130 не считается анемией; верхняя граница нормы сервисом не проверяется.
  • B9 и фолаты объединены в один анализ. «Билирубин» в документе сохранён как общий термин; в suggestedFeatures доступен только indirect_bilirubin (непрямой билирубин), не общий билирубин.
  • Списки анализов предложены для обсуждения с врачом и сверки с имеющимися результатами. MMA остаётся опциональным; suggestedFeatures содержит лишь отсутствующие входы. Полный список в тексте служит контекстом интерпретации, а не утверждением, что каждый анализ отсутствует или нужен заново.
  • Двойное предложение о B12 в пациентском тексте убрано: предполагаемое состояние уже выводится отдельным заголовком сайта.

Новые расчёты используют версию 1.2. Сохранённые снимки рекомендаций остаются с исходной версией; чтобы увидеть новые тексты, нужен новый расчёт.
