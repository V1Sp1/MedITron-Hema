# Запуск Hema на macOS и Windows

Инструкция рассчитана на человека, который раньше не запускал программы из исходного кода. Вам потребуется один раз установить Python и библиотеки. Затем сайт будет работать на вашем компьютере, без аккаунта Codex, облачного API и повторного обучения модели.

## Ограничение этого выпуска

Используйте только синтетические или действительно обезличенные данные. Реальные идентифицируемые анализы и клинические отчёты пока не допускаются. Перед импортом/расчётом нужно явно подтвердить исследовательский режим и вид данных. Это не юридическое согласие. Врачебные учётные записи для проверки также делайте вымышленными.

## Что нужно знать перед началом

Архив — упакованная папка. Его нужно распаковать целиком. Python — программа, которая запускает наш сервер. Терминал/PowerShell — окно для ввода команд. Виртуальное окружение .venv — отдельная папка библиотек проекта; оно создаётся на каждом компьютере заново. Сервер — программа в этом окне; пока она работает, сайт открывается в браузере. 127.0.0.1 означает ваш собственный компьютер, не внешний сайт.

Используйте Python 3.12 (последнюю доступную patch-версию этой ветки для вашей ОС), 64-bit. Обученные веса проверены с Python 3.12.14 и закреплёнными библиотеками. Новейшая другая ветка Python не считается автоматической заменой: у неё могут отсутствовать совместимые пакеты. На Windows основной маршрут рассчитан на x64; Windows ARM не проверен. На Mac проверен Apple Silicon; Intel Mac требует отдельной проверки совместимости wheel-пакетов. В pyproject указан общий минимум 3.11, но для этой передачи выбран конкретно 3.12 ради совместимости weights.

Интернет нужен для скачивания Python и первоначальной установки библиотек. Архив содержит код, веса, локальные шрифты/JS-библиотеки, но не офлайн-установщики Python-зависимостей. В процессе расчёта внешние медицинские API не используются. Внешние ссылки справочной информации могут открывать интернет-страницы только при переходе пользователя.

Нет измеренных минимальных системных требований. Практический ориентир для обычного запуска — современный 64-bit компьютер, несколько ГБ свободного места и памяти. Это ориентир установки, не нагрузочный benchmark. Повторное обучение требует больше времени и не нужно для пользования.

## Распаковка

1. Сохраните ZIP на компьютер.
2. На Mac дважды щёлкните ZIP. На Windows правой кнопкой → «Извлечь всё» → «Извлечь».
3. Переместите распакованную папку Hema в удобное место. На Windows удобно C:\Hema, на Mac — домашняя папка/Hema. Не храните рабочий проект внутри самого ZIP.
4. Откройте папку. В ней одновременно должны лежать START_HERE.html, pyproject.toml, START_MAC.command, START_WINDOWS.bat, backend, frontend, experiments и data. Если видите только одну папку Hema, зайдите в неё.
5. Проверьте, что есть experiments/baseline_v1/models/selected.joblib. Это готовая модель. Распаковывайте весь архив, не только скрипт запуска.

## macOS установка Python

1. Откройте официальный [сайт Python](https://www.python.org/downloads/macos/).
2. Найдите ветку Python 3.12 и installer для macOS. Скачайте установщик .pkg. Если последняя security patch-версия предлагается только как source, выбирайте доступный macOS installer ветки 3.12; не скачивайте source archive для ручной сборки новичком.
3. Откройте .pkg и пройдите обычную установку. Не нужно устанавливать Codex, Xcode целиком или Node.js для основного запуска.
4. Через Spotlight (Command+Space) найдите «Терминал»/Terminal и откройте.
5. Введите следующую команду и нажмите Enter:

```sh
python3.12 --version
```

Ожидается Python 3.12.x. Если команда не найдена, закройте/откройте Terminal; проверьте завершение установки. Если доступен только python3, выполните python3 --version: продолжайте им только при 3.12.x. Команды ниже используют python3.12.

## macOS простой первый запуск

1. В Terminal напечатайте `cd ` с пробелом после cd.
2. Перетащите папку Hema из Finder в это окно. Terminal подставит полный путь.
3. Нажмите Enter. Теперь команды выполняются из папки проекта.
4. Введите:

```sh
bash START_MAC.command
```

Скрипт проверит Python 3.12, создаст .venv, установит библиотеки при первой установке и запустит сервер. Не закрывайте окно. Подождите: первый запуск может занять несколько минут из-за скачивания. Браузер откроется после ответа сервера; если не открылся, вручную введите `http://127.0.0.1:8000/`.

После настройки можно пробовать двойной щелчок START_MAC.command. Если macOS не разрешает запуск/отсутствуют права, используйте Terminal-команду выше; она не требует менять системные политики. Не отключайте защиту macOS целиком ради скрипта.

## macOS ручной способ

Этот способ полезен, если нужен полный контроль команд. Откройте Terminal в папке проекта как описано выше. Копируйте по одной строке, каждый раз нажимайте Enter и дождитесь завершения:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -c requirements-runtime.txt -e '.[server,model]'
.venv/bin/python -m backend
```

Одинарные кавычки вокруг extras нужны shell. После последней команды окно остаётся занятым сервером — это нормально. Откройте браузер и адрес `http://127.0.0.1:8000/`. Activate окружения не требуется: используется точный путь к Python.

## macOS OCR сканов

Текстовые PDF работают без OCR. Чтобы распознавать сканы, нужен компилятор Swift из Xcode Command Line Tools. Если вы планируете использовать сканы, один раз в Terminal выполните:

```sh
xcode-select --install
```

Подтвердите установку системных инструментов и дождитесь окончания. Проверка:

```sh
swiftc --version
```

Для OCR используется Apple Vision локально. Он может ошибаться в цифрах, именах и единицах: обязательно сверяйте форму с PDF. Для запуска только текстовых PDF используйте `.venv/bin/python -m backend --ocr off`. На публичном скане Lab4U качество ограничено; отсутствие ошибки сервера не доказывает правильность распознавания.

## Windows установка Python

1. Откройте официальный [сайт Python для Windows](https://www.python.org/downloads/windows/).
2. Найдите installer Python 3.12 для Windows 64-bit/x86-64. Если последняя security patch-версия не имеет installer, используйте доступный 64-bit installer ветки 3.12. Не выбирайте source archive, embeddable package или ARM-пакет для обычного x64 компьютера.
3. Запустите установщик. В классическом installer отметьте «Add python.exe to PATH» и установку Python Launcher (`py`), если пункт доступен. Завершите установку.
4. Закройте ранее открытые командные окна. Нажмите Win, напечатайте PowerShell и откройте Windows PowerShell/Terminal с профилем PowerShell.
5. Выполните:

```powershell
py -3.12 --version
```

Ожидается Python 3.12.x. Если py не найден, выполните `python --version`. Это допустимая замена только при ответе 3.12.x. Если вместо версии открывается Store, переустановите официальный Python с launcher/PATH; в настройках Windows проверьте конфликтующие App execution aliases для python.exe. Не продолжайте с произвольной другой версией.

## Windows простой первый запуск

1. В распакованной папке дважды щёлкните START_WINDOWS.bat.
2. Откроется командное окно. Скрипт выбирает py -3.12, а при отсутствии launcher пробует python с обязательной проверкой 3.12. Перед запуском задано `PYTHONUTF8=1`: Python и его дочерние процессы используют режим UTF-8, чтобы чтение текстовых файлов проекта не зависело от системной кодировки Windows.
3. При первом запуске создаётся .venv и скачиваются библиотеки. Подождите до сообщения о запуске сервера. Интернет нужен на этом этапе.
4. Браузер откроется автоматически, если сервер ответил. Если этого не произошло, откройте `http://127.0.0.1:8000/` вручную.
5. Не закрывайте командное окно, пока пользуетесь Hema. Кодировка сообщений launcher на Windows намеренно ASCII, чтобы окно не искажало текст; русская инструкция и сайт находятся в HTML.

BAT не требует PowerShell execution policy и активации venv. Отсутствие OCR на Windows не блокирует ручной ввод, CSV/XLSX, модель, текстовые PDF и экспорт отчётов.

## Windows ручной способ

1. Откройте папку проекта в Проводнике.
2. Нажмите на адресную строку, скопируйте путь (например C:\Hema).
3. Откройте PowerShell и перейдите в эту папку, заменив пример реальным путём:

```powershell
cd "C:\Hema"
```

4. Выполняйте по одной строке:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -c requirements-runtime.txt -e ".[server,model]"
.\.venv\Scripts\python.exe -m backend --ocr off
```

Если py отсутствует, а python --version показал 3.12, замените только первую строку на `python -m venv .venv`. У остальных строк остаётся путь .venv\Scripts\python.exe. Activate.ps1 не нужен. Не надо менять Set-ExecutionPolicy.

5. Откройте браузер на `http://127.0.0.1:8000/`. Не открывайте frontend/index.html двойным щелчком для работы сервиса: это не запуск сервера.

## Проверка готовности

Откройте `http://127.0.0.1:8000/api/models/status`. Браузер покажет технический JSON. Найдите `state`: должно быть `ready`, `connected`: true и непустая modelVersion. Поле calibrated:false ожидаемо и описывает отсутствие калибровки. Статус unavailable — ошибка weights/библиотек, не успех установки. При --no-model будет disabled, это намеренно ограниченный режим.

Откройте `http://127.0.0.1:8000/api/health`: при штатной модели ожидается status ok. В интерфейсе выберите роль, прочитайте блок исследовательского режима, выберите «Синтетические», отметьте подтверждение и нажмите «Начать исследовательскую работу». Затем введите возраст 42, пол «женский», Hb 108. Рассчитайте: статус Hb ниже порога и предупреждение о недостатке анализов ожидаемы. Это проверка связи браузера/сервера, не испытание точности модели.

Условия исследовательской работы теперь показаны во всплывающем окне. Выберите вид данных и отметьте подтверждение, затем нажмите «Продолжить». В действующей часовой сессии окно не повторяется при перезагрузке; условия доступны по ссылке в форме. Крестик позволяет посмотреть интерфейс, но импорт и расчёт до подтверждения отключены.

Для проверки более полной цепочки импортируйте `examples/synthetic_panel.csv`, выберите строку и рассчитайте. Панель синтетическая, не является медицинским образцом пациента. Для PDF используйте включённый синтетический `output/pdf/test_uploads/01_cbc.pdf`, проверьте числа/единицы после извлечения, введите пол/возраст, затем рассчитайте. Другие готовые примеры находятся в output/pdf/test_uploads. На Windows не используйте скан Lab4U для ожидаемой автоматической OCR-проверки.

«Посмотреть пример» демонстрирует интерфейс заранее подготовленными числами и не проверяет настоящую модель. Для проверки weights вводите данные самостоятельно.

## Как пользоваться

1. Выберите роль пациента или врача. Врач входит по учётной записи организации: сначала создайте запись через python -m backend.accounts create LOGIN. Пароль запрашивается в терминале; подробности в backend/AUTH.md. Пациенту пароль не нужен, но его записи доступны только своей часовoй research-cookie.
2. Подтвердите research-режим/выбранный вид данных. Затем заполните форму вручную, импортируйте CSV/XLSX либо загрузите PDF. Можно оставить отсутствующие дополнительные анализы пустыми.
3. Указывайте значения в единицах рядом с полем. Не вводите 10.8 для Hb в г/л, если в бланке 10.8 г/дл: это 108 г/л. PDF-путь переводит только поддержанные единицы; CSV/XLSX должны уже иметь единицы кейса.
4. При PDF внимательно проверьте форму по оригиналу. Повторы/границы/неизвестные единицы не выбираются автоматически. Отчёт нельзя считать проверенным потому, что текст распознался.
5. Нажмите расчёт. Прочитайте Hb, модельный вывод, полноту и предупреждения вместе. Неопределённость — допустимый результат прототипа.
6. «Сохранить PDF» скачивает файл отчёта. «Печать» открывает диалог ОС, JSON сохраняет техническую структуру.
7. Чтобы изменить анализы, вернитесь к вводу; изменение сбросит старый результат.

## Повторный запуск и остановка

Повторно открывайте START_WINDOWS.bat или выполняйте `bash START_MAC.command` из папки проекта. Существующее окружение с установленным пакетом используется повторно, без обязательной переустановки библиотек. Если перенесли папку проекта после установки, editable paths могут устареть: запустите установку заново через Python вашей .venv `-m pip install -c requirements-runtime.txt -e ".[server,model]"`, либо создайте новое окружение по ручной инструкции. Переносить .venv между компьютерами нельзя.

Остановка: вернитесь в окно сервера, нажмите Ctrl+C (на Mac именно Control, не Command). Дождитесь завершения. После остановки адрес сайта не отвечает — нормально. Перезапуск удаляет все новые медицинские записи и PDF из оперативной памяти. Учётные записи и хеши ключей сохраняются отдельно.

Если порт 8000 занят, сначала остановите прежний экземпляр. Если нужен другой порт:

macOS:

```sh
.venv/bin/python -m backend --port 8001
```

Windows:

```powershell
.\.venv\Scripts\python.exe -m backend --port 8001 --ocr off
```

Откройте `http://127.0.0.1:8001/`. Не запускайте отдельный dev-фронтенд 5173 для этого случая без настройки его API-адреса.

## Где хранятся данные и как очистить

Новые медицинские отчёты/наблюдения/исходные PDF находятся в RAM не более часа от подтверждения режима. Чтение не продлевает срок. «Очистить» удаляет записи текущего сеанса и cookie; выход врача тоже удаляет их. Перезапуск сервера уничтожает RAM Store. Скачанные вами PDF/JSON и распечатки остаются у вас — удалите отдельно, если они больше не нужны.

Для PDF создаются приватные временные файлы внутри data/local/hema-live-*, затем удаляются после обработки. После аварийного выключения возможны остатки; отмеченные каталоги остановленных процессов очищаются при следующем запуске. RAM-only не гарантирует отсутствие swap/backup ОС.

В data/local/auth.sqlite3 сохраняются вымышленные тестовые записи, организации, хеши паролей/ключей и служебные сеансы. Эту папку не пересылайте коллегам и не заменяйте её данными из чужого архива. У получателя создаётся свой auth-контур.

Старая версия могла сохранять hema.sqlite3 и uploads. Новый сервер их не читает, но автоматически не уничтожает. Подробная проверка/удаление после остановки всех серверов: docs/legal/RETENTION_REQUESTS_INCIDENTS.md. Команда purge необратима и запрашивает отдельное текстовое подтверждение. Не путайте исходники кейса с runtime.

Для отдельного исследовательского экземпляра используйте --data-dir data/local-demo. Такие папки также исключены из нового ZIP. Обычная копия папки проекта через Проводник/Finder не применяет фильтр сборщика — передавайте готовый ZIP, проверенный по манифесту.

## Обновления безопасности Python

Испытания выполнены на 3.12.14. На 30.09.2026 вышел [Python 3.12.15](https://www.python.org/downloads/release/python-31215/) с новыми security-исправлениями. Ветка 3.12 больше не получает официальные бинарные installers; последний такой installer — 3.12.10. Его удобство не означает актуальной защищённости. Для локальной синтетической проверки старый installer может запустить прототип, launcher сообщает об устаревшей patch-версии. Для production администратор должен установить актуальную поддерживаемую сборку Python/ОС и повторно проверить зависимости/модели. Самостоятельно компилировать source новичку не требуется: при необходимости актуального runtime обратитесь к администратору проекта. Данный ZIP не включает управляемую runtime-сборку и не подтверждает её обновление на Mac/Windows.

## Частые проблемы

| Что видно | Причина и действие |
|---|---|
| Команда Python не найдена | Установите ветку 3.12 и откройте новое окно; проверьте python3.12/py |
| Can't open file / нет pyproject.toml | Вы находитесь не в корне; cd в папку с pyproject.toml |
| No module named backend / fastapi / catboost | Установка не завершена или выбран другой Python; используйте путь к .venv и повторите pip install |
| No matching distribution / build failed | Проверьте Python 3.12 64-bit, ОС/архитектуру, интернет и pip; не меняйте pinned версии наугад |
| Ошибка SSL при pip на Mac | При установке python.org найдите Install Certificates.command в папке Python 3.12 и выполните; при корпоративном proxy обратитесь к IT, не отключайте проверку TLS |
| pip не может скачать библиотеки | Проверьте сеть/proxy, повторите позже; сама модель уже в архиве |
| Address already in use | Работает другой сервер; Ctrl+C в его окне или используйте 8001 |
| Сайт не открывается | Сервер не запущен/закрыт; проверьте его окно и точный адрес http с 127.0.0.1 |
| state unavailable / predict 503 | Проверьте selected.joblib и model-зависимости; повторите установку тем же .venv Python |
| PDF не распознан на Windows | Вероятно скан; нужен текстовый PDF или ручной ввод, Apple Vision недоступен |
| На Mac swiftc не найден | Установите Command Line Tools, либо используйте --ocr off |
| Ошибки распознавания/не все значения в форме | Проверьте исходные строки, единицы и повторы; исправьте вручную |
| Недостаточно данных при рабочей модели | Мало лабораторных полей; не ошибка установки, specific cause подавлен политикой |
| PowerShell запрещает Activate.ps1 | Не активируйте окружение; используйте прямой путь python.exe как выше |
| Результаты демо кажутся идеальными | Это заранее подготовленный пример; проверьте ручной/файловый расчёт |

Если нужна помощь коллеги, сообщите ОС/архитектуру, вывод Python --version, шаг инструкции, ошибку терминала и state модели. Не отправляйте вместе с ошибкой реальные PDF пациента без необходимости.

## Дополнительные действия для разработчиков

Основные зависимости закреплены в pyproject.toml. Для Python-тестов добавьте test extra:

macOS:

```sh
.venv/bin/python -m pip install -e '.[server,model,test]'
.venv/bin/python -m unittest discover -s tests -v
```

Windows:

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[server,model,test]"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Для JS-тестов установите Node.js 20+ из официального [сайта Node.js](https://nodejs.org/en/download), затем в frontend выполните npm test. npm install не требуется. Разработка фронтенда: npm run dev, бэкенд отдельно на 8000. Основной способ запуска и без этого отдаёт страницы.

Для обучения нужны дополнительные пакеты ml_baselines/requirements.txt и новый output-каталог; подробности в руководстве модели. Архив содержит готовые weights и синтетические примеры. Исходный медицинский CSV исключён; для нового обучения нужен отдельно правомерно полученный источник. Обучение не является шагом установки.

## Что проверено и что нет

Передача проверяется на исходном macOS: Python/Node suites, целостность ZIP, наличие weights/источников, работа API из распакованной копии с новым временным хранилищем. Полная новая установка из интернета, GUI-двойной щелчок на другом компьютере, Windows и Intel Mac здесь не выполняются. На Windows исправлен путь завершения PDF-worker и проверена его логика управляемым тестом, но это не заменяет испытание на реальной ОС. Подробный итог в docs/07_VERIFICATION.md.
