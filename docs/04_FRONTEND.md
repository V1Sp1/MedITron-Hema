# Техническая реализация фронтенда Hema

Фронтенд состоит из обычных HTML-страниц, CSS и JavaScript ES-модулей. React/Vue, npm-библиотеки и облачная сборка для использования сервиса не нужны. FastAPI отдаёт `frontend/` напрямую. Node.js нужен для отдельного dev-сервера, копирующей сборки и автоматических JS-тестов.

## Страницы и пользовательский маршрут

index.html — главная с названием Hema by NeuroNiXxx, иллюстрацией и выбором роли. patient.html — форма и результат пациента; doctor.html — тот же процесс с врачебным представлением. Каждая страница роли сначала показывает форму. После расчёта открывается отдельный экран результата с hash #result; возврат к вводу сохраняет значения. История браузера поддерживает переходы. «Сменить роль» возвращает к выбору, «О проекте» открывает информационное окно.

Форма поддерживает ручной ввод, одну строку CSV/XLSX и пакет PDF. Семь вкладок группируют все 35 лабораторных показателей: кровь, железо, витамины, микроэлементы, воспаление, почки/обмен, гемолиз. Возраст/пол задаются отдельно. Пустые поля — неизвестные значения, не нормальные результаты. Требуется возраст 18–120, пол и Hb; дополнительные анализы необязательны, но влияют на полноту и разрешённый вывод.

## Состояние формы и результат

Форма, выбранные файлы, демо/реальный источник, ID PDF-наблюдения и текущий отчёт — разные состояния. Изменение ввода сбрасывает устаревший отчёт и снимает демо. Запросы используют AbortSignal, чтобы старый ответ не подменил результат после смены данных. Результат появляется только после завершения API-прогноза и получения рекомендаций. Ошибка API показывается человеку; она не заменяется случайным демо или браузерным правилом.

При PDF первый клик отправляет файлы и заполняет черновик. Затем пользователь проверяет/исправляет значения. Следующий расчёт передаёт observationId, reviewedObservation=true и сохранённую revision. Клиент хранит ревизии Map по ID и обновляет их по ответу. Если ревизия не известна, просит загрузить и проверить пакет заново.

## Режимы исполнения

На hostname localhost или 127.0.0.1 config.mode='api'. На порту 5173 baseUrl указывает http://127.0.0.1:8000; на серверном порту используется тот же origin. Поэтому даже dev-фронтенд на localhost ожидает бэкенд. Сам факт открытия страницы через Node.js не создаёт подключённую модель.

На других hostname предусмотрен local-режим: только JS-правило Hb, без настоящего model inference и PDF-парсера. Это вспомогательное поведение статического просмотра, не основной способ запуска. HTML через file:// не поддерживает рабочий сервис и ES-модули так же, как HTTP: для использования запускайте Python.

local-режим хранит данные только в оперативной памяти, не localStorage. api-режим отправляет выбранные inputs/PDF локальному серверу и сохраняет их в data/local. Перезагрузка браузера очищает текущую форму, но не удаляет записи на сервере. Выбор роли не аутентифицирует пользователя.

## CSV импорт

CSV читается File API в браузере. Поддерживаются BOM, разделители запятая/точка с запятой, кавычки и десятичная запятая при корректной структуре. Лимит 5 МБ и 10 000 строк. Заголовки должны быть техническими ключами словаря; регистр/написание значимы. Импортируется одна выбранная запись, не весь массив пациентов. Идентификаторы и целевые столбцы игнорируются, а API при прямом передавании неизвестных keys их отклоняет.

Все числовые значения CSV/XLSX должны уже быть в единицах кейса. Импорт таблицы не угадывает и не пересчитывает внешние единицы. Например Hb должен быть в г/л, не г/дл; MCHC тоже г/л. Для нестандартной единицы переведите значение осознанно или используйте проверенный PDF-путь с поддержанной конверсией. Не заменяйте пропуски нулями.

Пример синтетической строки для проверки, не данные пациента:

```csv
age_years,sex,hemoglobin,RBC,hematocrit,MCV,MCH,MCHC,RDW,platelets,WBC,ferritin,TSAT,vitamin_B12,folate,CRP
42,F,108,4,33,78,25,320,17,320,6.5,9,10,340,12,1
```

Эта панель нужна для проверки взаимодействия компонентов; правильность результата не является оценкой медицинского качества.

## XLSX импорт

JSZip распаковывает контейнер XLSX локально. DOMParser читает XML workbook, relationships, sharedStrings и первого видимого sheet. Внешние relationships отвергаются. Hidden/veryHidden листы пропускаются. Для ячеек учитываются shared string, inline string и числовые значения. Формулы не исполняются: используется сохранённый cached value, отсутствие его вызывает просьбу пересчитать и сохранить книгу. Ошибочные ячейки отклоняются.

Лимиты: распакованное содержимое 30 МБ, 10 000 записей плюс header, до 201 столбца. Колонки восстанавливаются из адреса ячейки, пустоты сохраняются. Матрица превращается в CSV-строки и обрабатывается общим parseCSV. Имена остальных видимых листов не означают, что они объединяются; выбирается первый.

## API клиент и проверка ответа

createClient принимает настройки и fetch для удобства тестирования. post автоматически выбирает JSON или multipart. При ошибке пытается извлечь строковый detail; иначе показывает код. Предварительно screen нормализует whitelist и правило Hb. Для настоящего отчёта проверяются audience, непустой reportId, булевый anemia, согласованность с браузерным Hb, списки warnings и массивы scores (число, конечность, 0–1). Затем запрашиваются фразы с тем же role/reportId, проверяется структура items/conclusions/dataSufficiency.

Клиент объединяет серверный report и фразы: recommendations, recommendationVersion/status, recommendationConclusions, insufficientData, clinicalReviewStatus. Предупреждения дедуплицируются. Свободный label и проценты не используются как собственная диагностика браузера. Математическое решение остаётся на сервере.

## Результат и экспорт

Пациент получает понятный статус, выводы, полноту и следующие шаги. Врач дополнительно видит исследовательские оценки дефицитов и классов, если их передал API. Числа примеров получены реальной моделью на вымышленных входах; происхождение и версия указаны явно. При sparse policy причинные scores не передаются. Для классов scores сервер даёт список только при анемии.

«Сохранить PDF» создаёт PDF в браузере через pdf-lib/fontkit и встраивает локальный IBM Plex Sans. Это скачивание blob application/pdf, не скачивание HTML с расширением PDF. Русский текст доступен для поиска. В PDF включены все 35 показателей с единицами или отметкой отсутствия, возраст/пол и версия модели. Длинные строки переносятся, длинные отчёты делятся на страницы. «Печать» вызывает window.print и CSS print-версию текущей страницы; в диалоге ОС можно выбрать принтер или PDF. JSON сохраняет машинную структуру отчёта, включая версии и ограничения.

HTML-тестовая утилита reportHTML не является основным экспортом. escapeHTML экранирует пользовательские строки для HTML. Временные object URL отзываются после скачивания.

## Визуальная система

Палитра ориентируется на дизайн-систему СУ: #0DEACF, #103648, #1E465B, #E3EEF1; IBM Plex Sans/Mono включены локально. Главная использует художественную панораму эритроцитов с мягкими переходами, не диагностический снимок. Промпты сохранены рядом. Responsive CSS меняет отступы и композицию; есть клавиатурная навигация и диалоговые окна. Шрифты/JS-библиотеки не запрашиваются из CDN при основном запуске.

Окна конфиденциальности описывают RAM-хранение до часа, приватные временные файлы, auth.sqlite3 и отдельное удаление скачанных/старых копий. Условия исследовательского режима прямо отличают подтверждение от юридического согласия. Оператор и основание каждой клиники/лаборатории требуют оформления до реального запуска; шаблоны в docs/legal.

## Сборка и разработка

package.json задаёт type=module, Node >=20 и scripts dev/build/test. npm install не требуется, зависимости vendored. serve.mjs отдаёт frontend на 127.0.0.1:5173; API остаётся на 8000. build.mjs копирует index/patient/doctor/favicon/src в dist без bundler/minifier. backend отдаёт исходную frontend-папку, а не dist. После изменения src существующий dist нужно пересобрать, если его передают отдельно.

```sh
cd frontend
npm run dev
npm test
npm run build
```

Альтернатива: `node scripts/serve.mjs`, `node scripts/build.mjs`. На Windows для тестов используйте `npm test`: Node получает шаблон из package script. На macOS из корня также можно запускать `node --test frontend/tests/*.test.mjs`; для Windows используйте `npm test` из frontend.

## Проверки

api.test.mjs проверяет клиент и ошибки; backend.test.mjs — взаимодействие с server fixture; screening.test.mjs — Hb/CSV/whitelist; recommendations.test.mjs — отображение выводов/полноты; pdf.test.mjs — кириллицу/переносы/длинные отчёты. tests/xlsx.html — отдельный браузерный набор XLSX, доступный на dev-сервере и не включаемый в dist. scripts/check-pdf.mjs создаёт образцы PDF в preview/pdf для просмотра.

Для ручной проверки пройдите обе роли, ручную панель, CSV, текстовый PDF, ошибку сервера, возврат к форме, изменение после результата, PDF/JSON/печать и мобильную ширину. Настоящий модельный прогноз проверяйте без «Посмотреть пример».

## Полные примеры в «Посмотреть пример» — 2026-10-05

Выберите роль → «Посмотреть пример» → сценарий над результатом. Доступны 15 вымышленных панелей / 30 отчётов. Расширенные примеры по железу, B12, фолатам, B6, меди, сочетанию, воспалительному компоненту, почечным показателям и Hb выше порога имеют 34–35 лабораторных значений. Дополнительно показаны Hb = 120/130, неопределённость при полной панели, расхождение классификатора с Hb, ОАК 9/35 и один Hb.

Все вердикты и оценки получены через настоящий ModelService на доверенных весах hema-baseline-v1-1dc7ef11da40. Фразы 1.2 выбраны настоящим селектором, без заданного вручную вердикта и без simulation. Для первых восьми профилей и normal модель дала согласованный вывод. CBC-пример использует соответствующую ветку и сохраняет ограничение неполной панели. Три неоднозначных профиля и один конфликт подавляют конкретную причину и специфические фразы, сохраняя вычисленные оценки. Sparse оставляет правило Hb и ограничения, без числовых scores.

У врача при доступных данных видны пять оценок дефицитов; при анемии — все 12 оценок классов. У пациента сохранены простые объяснения и следующие шаги. В раскрываемом блоке «Показатели примера» — вся панель, единицы, отсутствующие анализы и версии. PDF/JSON сохраняют происхождение и полноту; числа не обозначаются иллюстративными или клиническими вероятностями.

Просмотр использует готовый снимок и не запускает API, не создаёт серверных записей. Переключение подставляет значения в форму; правка снимает демо. Повторный API-расчёт с теми же весами/правилами/входами воспроизводит результат. С другим model-bundle снимок может отличаться: его версия указана отдельно. Готовые снимки включены в src/dist, Python при просмотре не нужен.

Файлы для проверки: examples/full-demo/input_panels.csv (15 строк, только 37 входов), reports.json (оба представления), README.md (порядок строк), hema-full-examples.zip. Готовые PDF врача/пациента: output/pdf/full-examples. Полностью вымышленные значения не взяты из CSV пациентов и не являются эталонными диагнозами.

После изменения фраз/весов запустите `.venv/bin/python scripts/build_demo_scenarios.py`, затем сборку frontend. Проверено 31 Node-тестом, тремя Python-тестами (сверка с настоящей моделью/селектором, отсутствующие weights и CSV), переключением всех 30 отчётов и экспортом PDF в браузере. У двух готовых PDF проверены текст и все семь отрендеренных страниц. Исходные данные, веса и политика принятия решений не менялись.

## Подтверждение режима и очистка

privacy.js устанавливает небольшую строку состояния в форму и отдельный native dialog вне формы. Окно открывается перед началом работы без действующего сеанса; после подтверждения закрывается, при перезагрузке в том же часовом сеансе не повторяется. Краткая ссылка позволяет вновь прочитать условия; подробности раскрываются через details. Окно можно закрыть крестиком/Escape/кликом по фону, но это не даёт доступа к импорту или расчёту. Выбор вида данных не предзаполнен: нужен явный выбор и checkbox. Ответ первоначального status игнорируется, если состояние уже изменено, чтобы поздний ответ не восстановил очищенный сеанс. До подтверждения researchOnly и synthetic/anonymized кнопка расчёта и файловые input отключены, drop перехватывается до чтения. Модельное API тоже проверяет grant независимо от UI. Status восстанавливает только действующий серверный сеанс; истечение часа сбрасывает форму/результат. 428 переводит gate в неподтверждённое состояние. Галочка не медицинское согласие.

«Очистить» отменяет текущий запрос/устаревшие операции, очищает browser-state и отправляет DELETE /api/privacy/session с credentials/X-Hema-Client. Ошибка сервера отображается, успешное удаление не имитируется. Сервер проверяет живой grant перед сохранением результата. Демо остаётся подготовленной исследовательской иллюстрацией и не создаёт медицинский сеанс. Scores UI/PDF имеют decimal 0–1, без процента болезни, и используют канонические Scores с legacy fallback. Отдельная кнопка входа в шапке сохранена.
