# Hema · by NeuroNiXxx — фронтенд скрининга

Локальный прототип по кейсу Сеченовского университета. HTML, CSS и модульный JavaScript; JSZip включён в исходники с лицензией для чтения XLSX. Нужен Node.js 20+; установка npm-зависимостей не требуется.

```sh
cd frontend
npm run dev
# http://127.0.0.1:5173
npm test
npm run build
```

Без npm: `node scripts/serve.mjs`, `node --test tests/*.test.mjs`, `node scripts/build.mjs`. Готовый статический фронтенд находится в `dist/`.

## Вход врача

Кнопка «Войти» в шапке каждой страницы открывает вход с учётной записью организации. При выборе врача требуется тот же вход. На локальном сервере есть окно логина/пароля, срок сеанса 8 часов и выход. В статическом режиме вход недоступен: откройте сайт через Python-сервер. Пациентский режим открыт. Учётные записи создаёт администратор по [инструкции](../backend/AUTH.md).

## Возможности

- Ручной ввод возраста, пола и 35 лабораторных показателей; пропуски сохраняются.
- Стартовый выбор роли (`index.html`), отдельные страницы `patient.html` и `doctor.html` с разными представлениями и методами прогноза. На странице роли сначала видна только форма; после расчёта открывается отдельный экран результата (`#result`). Возврат к вводу сохраняет значения, история браузера поддерживает переходы между шагами.
- Семь мини-вкладок: кровь, железо, витамины, микроэлементы, воспаление, почки/обмен, гемолиз. Все 35 показателей распределены без повторов.
- CSV/XLSX до 5 МБ / 10 000 строк. CSV: запятая или точка с запятой, BOM, кавычки, десятичная запятая. XLSX: первый видимый лист, текстовые/числовые ячейки, кэшированные формулы. Выбор одной записи для отчёта.
- Пакет из нескольких PDF: добавление/удаление файлов, до 10 файлов / 20 МБ каждый / 60 МБ на пакет. Подключён локальный Python API: после распознавания открывается форма проверки; повторное нажатие создаёт отчёт.
- Явный белый список 37 входных признаков. Все целевые метки и идентификаторы игнорируются.
- Анемия по правилу кейса: Hb < 120 г/л у женщин, < 130 г/л у мужчин; только взрослая популяция.
- Отдельные кнопки «Сохранить PDF» и «Печать»: первая локально создаёт настоящий PDF с доступным для поиска русским текстом и сразу скачивает файл; вторая открывает системный диалог печати. Используются локальные pdf-lib 1.17.1, fontkit 1.1.1 и IBM Plex. Промежуточный HTML-файл не скачивается. Дополнительный экспорт JSON. Для врача — блоки исследовательских scores при ответе модели или при явно выбранном демо.
- Сброс устаревшего отчёта при изменении ввода, отмена старых запросов, клавиатурная навигация, адаптивный интерфейс.

## Ограничения и интеграция

При основном запуске через `python -m backend` на localhost включён локальный API с обученными моделями baseline_v1 и каталогами фраз 1.2. Ошибки модели не подменяются демо. «Посмотреть пример» открывает 15 вымышленных панелей / 30 отчётов для обеих ролей. Каждый пример содержит сохранённый настоящий расчёт доверенной модели, соответствующие фразы, заключения, полноту и ограничения. Врач видит пять оценок дефицитов и 12 оценок классов при анемии; при одном Hb оценки подавляются с объяснением причины. Исходные значения доступны в раскрываемой таблице. PDF содержит все показатели и происхождение; JSON — полную структуру. [Руководство фронтенда](../docs/04_FRONTEND.md).

API в `../backend/` подключён через `src/api.js`; сайт и API можно обслуживать одним Python-процессом на 8000, отдельный Node dev-сервер 5173 обращается к API 8000. PDF требуют проверки/подтверждения; совместимые единицы переводятся, повторы не выбираются автоматически. Черновые фразы и покрытие не прошли клиническую валидацию. Роль задаёт представление, не контроль доступа.

Единицы всех 37 входных признаков установлены по предоставленному `variables.xlsx` и отображаются в интерфейсе; канонический словарь — `../data/feature_dictionary.json`, отчёт — `../FEATURE_UNITS.md`. Ферритин указан в мкг/л (численно равен нг/мл), MCHC — в г/л, MMA — в мкмоль/л. Автоматический пересчёт внешнего CSV пока не подключён: импорт должен использовать единицы кейса. Все отсутствующие анализы остаются `null`. Проверка типов не является проверкой физиологической правдоподобности.

`src/screening.js` — правило Hb и CSV; `src/api.js` — отдельные вызовы прогноза/рекомендаций/PDF; `src/data.js` — признаки и группы; `src/xlsx.js` — чтение XLSX; `src/export.js` — печать и скачивание PDF/JSON; `src/pdf-report.js` — создание PDF; `src/information.js` — окна о проекте, конфиденциальности и обработке (HTML-шаблон отчёта сохранён как тестовая утилита); `src/app.js` — страницы и взаимодействия; `src/styles.css` и `src/pages.css` — оформление. `tests/xlsx.html` — браузерные проверки XLSX, доступны через dev-сервер и не включаются в сборку.

В api-режиме после явного research-подтверждения выбранные значения/пакет PDF передаются только локальному сервису. Новые медицинские records/PDF находятся в RAM Store до часа, доступны своей cookie/врачебной записи, удаляются очисткой/logout/TTL/перезапуском. Временные worker-файлы удаляются после обработки. auth.sqlite3 хранит логины/организации/хеши отдельно. Старые базы/скачанные копии не уничтожаются автоматически. В local-режиме ввод остаётся в RAM браузера. Шрифты/JS включены локально; облачной медицинской обработки нет.

## Обработка данных и юридический статус

В api-режиме после явного research-подтверждения выбранные значения/пакет PDF передаются только локальному сервису. Новые медицинские records/PDF находятся в RAM Store до часа, доступны своей cookie/врачебной записи, удаляются очисткой/logout/TTL/перезапуском. Временные worker-файлы удаляются после обработки. auth.sqlite3 хранит логины/организации/хеши отдельно. Старые базы/скачанные копии не уничтожаются автоматически. В local-режиме ввод остаётся в RAM браузера. Шрифты/JS включены локально; облачной медицинской обработки нет.

В шапке восстановлена кнопка «О проекте», у врача и в отчёте явно указано: сервис поддерживает решения, не устанавливает диагноз и не назначает лечение. В форме и футере есть ссылки на конфиденциальность и обработку данных. Тексты описывают фактическое поведение прототипа и не оформлены как юридическое согласие. Для публичного запуска ожидаются оператор, контакты, сроки хранения, порядок обращений и отдельное согласие. Не считать открытие окна согласием.

## Проверка PDF

`node scripts/check-pdf.mjs` создаёт четыре тестовых отчёта в `preview/pdf/`: пациент, врач, локальное правило и длинные рекомендации. Русский текст и состав отчётов проверены через pypdfium2, страницы визуально просмотрены; перенос длинных строк и страниц покрыт Node-тестами. В браузере кнопка PDF формирует документ без ошибки; событие загрузки файла не предоставлено встроенным браузером. Проверка системного диалога печати в обычном браузере остаётся отдельной проверкой.

## Обновление примеров рекомендаций

`scripts/build_demo_scenarios.py` формирует вымышленные панели, выполняет ModelService.apply(screen(...)) на доверенных весах baseline_v1 и выбирает фразы настоящим phrases_for_report без simulation. Названия сценариев описывают входы, не назначают диагноз. Вердикты и числовые оценки не задаются вручную; для неопределённых/противоречивых ответов специфические фразы не добавляются.

Расширенные панели содержат 34–35 лабораторных значений; отдельно предусмотрены ОАК 9/35 (CBC-модели) и Hb 1/35 (sparse). Есть обе точные границы Hb 120/130, отсутствие анемии, пять отдельных дефицитов, сочетание железа/B12, воспалительный компонент, изменённые почечные показатели и неопределённость при расширенной панели. Это примеры поведения программы, не клиническая валидация.

После изменения весов/фраз выполните из корня:

```sh
.venv/bin/python scripts/build_demo_scenarios.py
```

Затем соберите frontend. Скрипт обновляет src/demo-scenarios.js и [CSV/JSON/ZIP](../examples/full-demo/README.md). CSV содержит только 37 входных колонок; порядок 15 записей совпадает со списком сайта. Никакие исходные записи пациентов не копируются.

Просмотр показывает готовый снимок, без API-запросов/сохранения. Изменение ввода снимает демо. Повторный расчёт через API воспроизводит снимок при тех же данных, весах и правилах; иная модель/версия может дать другой результат. Версия модели сохранена в каждом примере. Врачебный вход и подтверждение исследовательского режима для реального расчёта остаются обязательными.

Проверено: 31 Node-тест, три Python-теста на совпадение с настоящим inference и селектором, все 30 отчётов в браузере. Два готовых PDF в output/pdf/full-examples содержат русские фразы, исходные показатели и версии; все семь страниц отрендерены и визуально проверены. Пример врача — frontend/preview/hema-full-model-examples.jpg.

## Защищённый исследовательский выпуск

privacy.js показывает условия в отдельном native dialog перед чтением файлов и расчётом; synthetic/anonymized/researchOnly подтверждаются явно. После подтверждения остаётся компактная ссылка; действующий серверный сеанс восстанавливается без повторного окна и продления срока. Закрытие без подтверждения не разблокирует данные. Это не медицинское согласие. 428 сбрасывает gate; очистка отправляет DELETE с cookie/CSRF и показывает ошибку, если серверное удаление не удалось. UI/PDF scores 0–1 без процента заболевания. Реальные идентифицируемые данные/клиническое применение пока не допускаются. docs/09_SECURITY_REMEDIATION.md и docs/legal описывают исправления/условия выпуска.
