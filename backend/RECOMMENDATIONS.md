# Фразы и следующие действия Hema

Реализованы отдельные пулы по 20 фраз для пациента и врача. Версия `phrases-draft-1.2`, статус `draft`: это согласуемый черновик, а не клинически утверждённый файл. Тексты предлагают обсуждение/проверку и не назначают лекарства, дозы, сроки контроля или обязательный набор всех 35 анализов.

Источники ориентиров: [NICE NG239, распознавание и диагностика B12-дефицита](https://www.nice.org.uk/guidance/ng239/chapter/Recommendations), [BSG, железодефицитная анемия у взрослых](https://www.bsg.org.uk/getmedia/3e13dd5c-8e7b-4110-87c5-dcc1feee495d/Iron-Deficiency-Aneamia-in-Adults.pdf), [WHO, ферритин и воспалительный контекст](https://www.who.int/docs/default-source/micronutrients/ferritin-guideline/ferritin-guidelines-executivesummary.pdf). Это ориентиры для черновика, не проверка его применимости в российской клинической практике. Пороги Hb взяты из кейса. Упоминание B6/меди и классов модели основано на кейсе; качество распознавания этих состояний не доказано.

## Методы

- `GET /api/recommendations/catalog?audience=patient|doctor` — весь пул одной роли, условия, тип фразы, источники и версия.
- `POST /api/data-sufficiency` — `{inputs: {...}, audience: "patient"}`. Разрешены неполные/пустые входы; неизвестные поля и неверные типы отклоняются. Этот метод ничего не сохраняет.
- `POST /api/recommendations/preview` — `{inputs: {...}, audience: "doctor", verdict: {...}}`. Проверка сочетаний с явной симуляцией; без отчёта/записи в SQLite и без подключения настоящей модели.
- `POST /api/recommendations` — `{reportId: "UUID", audience: "patient"}`. Ответ по сохранённому отчёту; роль должна совпасть.

Фронтенд показывает отдельно «Что удалось оценить», «Недостаточно данных / Полнота данных» и «Следующие шаги». Эти разделы сохраняются в JSON, прямом PDF-экспорте и печати страницы. Демо остаётся отдельным режимом.

## Явный вердикт подключённой модели

```json
{
  "anemiaClass": "mixed_deficiency",
  "deficits": ["iron", "B12"],
  "inflammation": false,
  "status": "evaluated"
}
```

`anemiaClass` — одна из 12 категорий кейса или null; `deficits` — уникальные положительные решения iron/B12/folate/B6/copper либо null (решения не переданы); `inflammation` — bool/null, решение по цели inflammation_anemia, а не общий факт воспаления; `status` — evaluated, uncertain, out_of_scope. Класс конкретного одиночного дефицита может дать соответствующий код, но `latent_deficiency` не превращается автоматически в iron. Смешанный класс без списка компонентов сохраняет их неопределённость.

Настоящий отчёт должен содержать `modelConnected: true`, непустой `modelVersion` и `modelVerdict`. Подключённый baseline_v1 адаптер использует порог бинарного решения 0,5 и воздерживается при максимальной оценке класса <0,5; оценки не откалиброваны. Это политика прототипа, не клинически валидированный порог уверенности. Свободный текст prediction.label и массивы вероятностей не превращаются в положительные решения. Не допускается передавать вердикт в обычный /predict от пользователя; он доступен только в явно обозначенном /preview.

При противоречии Hb и класса, одиночного класса и списка дефицитов, неопределённом/неприменимом вердикте или малой панели конкретные сообщения о дефицитах подавляются. Класс anemia_other с положительным дефицитом/воспалительной целью, латентный класс с явно пустым списком дефицитов и воспалительная анемия при отсутствии анемии по Hb также считаются несогласованными. Пустой вердикт без решений не считается evaluated. Предположения iron+inflammation при анемии разрешено описывать вместе; их совместное распознавание на данных кейса не валидировано. Нет искусственной уверенности, назначения anemia_other из-за пропусков или произведения вероятностей для смешанного состояния.

## Полнота данных

Файл `data/sufficiency_policy.json`, версия `coverage-draft-1.0`:

- `insufficient`: отсутствует возраст/пол/Hb или меньше 5 лабораторных значений. Возраст/пол не считаются лабораторными показателями. Для валидных взрослых входов правило Hb по одному Hb доступно, этиологические сообщения подавляются.
- `limited`: не малая панель, но нет полного контекста Hb/MCV/MCH или одной из групп железо/B12/фолаты.
- `broader`: доступны Hb/MCV/MCH и ферритин, общий ИЛИ активный B12, фолаты. Это обозначение покрытия, не «достаточно для диагноза» и не измеренная точность.

Порог 5 и состав групп — техническая политика прототипа, без клинической или модельной валидации. `clinicalValidated: false`, `modelConfidence: null`. Нули остаются числами и считаются введёнными, а не пропусками; физиологическая правдоподобность отдельно не оценена. Отсутствующий анализ не становится отрицательным результатом. Не требуется заполнить все 35 показателей. Предлагаемые поля — только отсутствующие; общий и активный B12 являются альтернативами: если один уже указан, второй не предлагается автоматически. Контекст B12+фолаты учитывает оба варианта B12. Даты разных PDF не объявляются одним моментом обследования.

## Формат ответа

```json
{
  "status": "draft",
  "phraseFileVersion": "phrases-draft-1.2",
  "clinicalReviewStatus": "draft",
  "conclusions": [{"id": "patient.hb_low", "text": "..."}],
  "items": [{"id": "patient.follow_up", "text": "..."}],
  "dataSufficiency": {"level": "insufficient", "laboratoryCount": 1, "laboratoryTotal": 35, "summary": "...", "clinicalValidated": false},
  "insufficientData": {"active": true, "hasGaps": true, "summary": "...", "items": []},
  "verdictContext": {"modelState": "not_connected", "anemiaClass": null, "deficits": [], "inflammation": false, "reasonCodes": []},
  "simulation": false,
  "warnings": ["Часть текстов уточнена медицинской командой. Каталоги и правила достаточности остаются черновиком; клиническая валидация не выполнена."]
}
```

`items` совместим с прежним фронтендом, содержит только следующие шаги (до 4). Выводы — отдельный массив до 3; недостающие данные — до 4 сообщений. Идентификаторы стабильны, порядок по приоритету; каждое выбранное сообщение имеет reasonCodes, sourceIds, suggestedFeatures. В `dataSufficiency` также есть список доступных/отсутствующих входов, группы и альтернативы начальных тестов. Вывод «нет дефицита» не создаётся из неполной панели.

Причины несогласованности доступны в `verdictContext.reasonCodes` и в сообщении model_limited; адаптер сохраняет их также в `decisionReasonCodes`. Это коды проверки согласованности, не диагноз.

Для новых отчётов сохраняется `recommendationSnapshot`: фразы, версия и оценка полноты на момент расчёта. Редактирование каталога не меняет старый отчёт. Для прежних отчётов без snapshot рассчитывается текущий черновик. Параметр --phrase-file сохраняет прежний формат `{version, reviewed: true, items:[{id,text,audience,when:{anemia:true}}]}` и заменяет только массив items; черновые выводы/полнота и предупреждение остаются. Маркер reviewed — утверждение автора файла, не доказательство медицинской проверки.

## Правки медицинской команды — 2026-10-04

Источник — «Корректировка текста.docx»; неизменённая копия: `data/reference/medical_text_corrections_2026-10-04.docx`, SHA-256 в `catalog.sources.medical_team`. По порядку первых 12 тем документа обновлены 11 тем обеих ролей; у latent правок нет. Темы 13–20 и условия выбора сохранены. Добавленные списки исследований отражают редакционные предложения команды; не приписываются автоматически NICE/BSG/WHO. Статус draft сохранён: частичная редактура не подтверждает клиническую валидацию модели, правил покрытия и всех 40 фраз.

Интерпретации неоднозначностей:

- «Креатин» трактован как креатинин (`creatinine`) по контексту eGFR; это предположение требует подтверждения команды.
- Общий B12 указан приоритетно в пациентском тексте, активный — альтернативой. Уже введённый общий или активный B12 исключает предложение другого из suggestedFeatures. Оба не назначаются автоматически; NICE NG239 1.3.1 допускает один из них для начального исследования.
- «Hb в норме / выше порога» заменено на «не ниже порога анемии»: равенство 120/130 не считается анемией; верхняя граница нормы сервисом не проверяется.
- B9 и фолаты объединены в один анализ. «Билирубин» в документе сохранён как общий термин; в suggestedFeatures доступен только `indirect_bilirubin` (непрямой билирубин), не общий билирубин.
- Списки анализов предложены для обсуждения с врачом и сверки с имеющимися результатами. MMA остаётся опциональным; suggestedFeatures содержит лишь отсутствующие входы. Полный список в тексте служит контекстом интерпретации, а не утверждением, что каждый анализ отсутствует или нужен заново.
- Двойное предложение о B12 в пациентском тексте убрано: предполагаемое состояние уже выводится отдельным заголовком сайта.

Новые расчёты используют версию 1.2. Сохранённые снимки рекомендаций остаются с исходной версией; чтобы увидеть новые тексты, нужен новый расчёт.

## Полный пул

Ниже парные тексты одного сценария. Машинные условия и источники хранятся в JSON каждой роли.

### 01. hb_low (conclusion)

Пациент: Гемоглобин ниже порога.

Врач: Hb ниже порога для указанного пола. Этиология анемии не устанавливается по одному Hb; сопоставьте результат с клиникой и остальными исследованиями.

Условие: `{"anemia": true}`.

### 02. hb_not_low (conclusion)

Пациент: Гемоглобин не ниже порогового значения для анемии. Это не исключает дефициты железа или витаминов.

Врач: Hb не ниже порога анемии. Отсутствие анемии не является основанием исключать нутритивные дефициты.

Условие: `{"anemia": false}`.

### 03. iron (next_step)

Пациент: Предполагаемый дефицит железа. Обсудите с врачом дальнейший план обследования для выявления причины. Препараты и их дозировку должен назначать врач. Для уточнения причины рекомендуется обсудить анализы на LDH, билирубин, гаптоглобин, ретикулоциты, RDW, ферритин, TSAT, sTfR, CRP и показатели MCH/MCHC или свериться с уже имеющимися результатами на приёме у врача.

Врач: Рекомендуется проверить наличие железодефицита по маркерам обмена железа и оценить возможные причины, включая кровопотери и нарушение всасывания, с учётом анамнеза. Обратите внимание на результаты LDH, билирубина, гаптоглобина, ретикулоцитов, RDW, ферритина, TSAT, sTfR и CRP для уточнения причины патологии.

Условие: `{"deficit": "iron", "maxDeficits": 1}`.

### 04. B12 (next_step)

Пациент: Обсудите с врачом результаты B12, симптомы и принимаемые добавки. Рекомендуется оценить общий B12 (приоритетно; активный B12 — альтернатива), фолаты, креатинин, eGFR, ферритин, TSAT, CRP и ретикулоциты; MMA — по необходимости. Сверьтесь с уже имеющимися результатами и обсудите сдачу недостающих анализов.

Врач: Предполагаемый моделью B12-дефицит требует сопоставления с симптомами, факторами риска и общим или активным B12. При неопределённом результате рекомендуется рассмотреть MMA (опционально), eGFR и креатинин.

Условие: `{"deficit": "B12", "maxDeficits": 1}`.

### 05. folate (next_step)

Пациент: Обсудите с врачом результаты анализов фолатов и B12. Рекомендуется оценить фолаты, B12, креатинин, eGFR, ферритин, TSAT, CRP и гомоцистеин; MMA — по необходимости. Сверьтесь с уже имеющимися результатами на приёме у врача и обсудите сдачу недостающих анализов.

Врач: При предположении фолатного дефицита сопоставьте результаты фолатов, B12, креатинина, eGFR, ферритина, TSAT, CRP и гомоцистеина; MMA — опционально.

Условие: `{"deficit": "folate", "maxDeficits": 1}`.

### 06. B6 (next_step)

Пациент: Модель допускает недостаток B6. Обсудите с врачом результаты B6, ферритина, TSAT, CRP и RDW; при необходимости — сдачу недостающих анализов. Этот вывод сам по себе не является назначением добавок.

Врач: Предполагаемый моделью B6-дефицит сопоставьте с анамнезом и другими анализами. Рекомендуется оценить результаты B6, ферритина, TSAT, CRP и RDW; при необходимости — назначить недостающие исследования.

Условие: `{"deficit": "B6", "maxDeficits": 1}`.

### 07. copper (next_step)

Пациент: Модель допускает недостаток меди. Обсудите с врачом результаты меди, церулоплазмина, B6, ферритина, TSAT, CRP, B12 и фолатов; при необходимости — сдачу недостающих анализов.

Врач: При модельном предположении дефицита меди рекомендуется оценить медь, церулоплазмин, B6, ферритин, TSAT, CRP, B12 и фолаты, назначить недостающие исследования по показаниям и сопоставить результаты с инструментальной диагностикой.

Условие: `{"deficit": "copper", "maxDeficits": 1}`.

### 08. mixed (next_step)

Пациент: Модель допускает сочетание дефицитов: {deficits}. Обсудите их вместе с врачом. Рекомендуется оценить B12, фолаты (витамин B9), сывороточное железо, ферритин, TSAT, CRP, ретикулоциты, RDW и sTfR; свериться с имеющимися результатами и обсудить сдачу недостающих анализов.

Врач: Модель допускает сочетанный дефицит ({deficits}). Сопоставьте результат с анамнезом, симптомами и инструментальным обследованием для оценки возможных внутренних кровотечений. Рекомендуется оценить B12, фолаты (витамин B9), сывороточное железо, ферритин, TSAT, CRP, ретикулоциты, RDW и sTfR; при необходимости — назначить недостающие исследования.

Условие: `{"mixed": true}`.

### 09. inflammation (next_step)

Пациент: Модель допускает связь анемии с воспалением. Обсудите с врачом ферритин, TSAT, CRP, ретикулоциты, RDW и sTfR, включая необходимость недостающих анализов: воспаление и дефицит железа могут сочетаться.

Врач: При модельном предположении воспалительного компонента сопоставьте маркеры воспаления и обмена железа. Рекомендуется оценить ферритин, TSAT, CRP, ретикулоциты, RDW и sTfR; при необходимости — назначить недостающие исследования. Наличие воспаления не исключает одновременный железодефицит.

Условие: `{"inflammation": true, "anemia": true}`.

### 10. other (next_step)

Пациент: Модель не уточнила причину анемии. Для уточнения рекомендуется оценить ферритин, TSAT, CRP, креатинин, eGFR, ретикулоциты, RDW, B12, фолаты и гомоцистеин; MMA — по необходимости. Обсудите с врачом уже имеющиеся результаты и сдачу недостающих анализов. Возможна анемия неясного генеза; результаты необходимо сопоставить с симптомами и инструментальной диагностикой.

Врач: Категория anemia_other не подтверждает анемию неясного генеза после полного обследования. Продолжите дифференциальную оценку с учётом анамнеза, симптомов и инструментальной диагностики. Рекомендуется оценить ферритин, TSAT, CRP, креатинин, eGFR, ретикулоциты, RDW, B12, фолаты и гомоцистеин; MMA — опционально. При необходимости назначьте недостающие исследования.

Условие: `{"anemiaClass": "anemia_other"}`.

### 11. latent (conclusion)

Пациент: Гемоглобин не ниже порога анемии, но модель допускает дефицитное состояние. Такой вывод требует отдельной проверки.

Врач: Модель допускает дефицит без анемии. Нормальный Hb не отменяет верификацию соответствующих нутритивных гипотез.

Условие: `{"nonAnemicDeficit": true}`.

### 12. ferritin_context (next_step)

Пациент: Ферритин и показатель воспаления уже добавлены. Обсудите их вместе с врачом: воспаление может влиять на ферритин. Для уточнения картины рекомендуется оценить ретикулоциты, RDW, sTfR и TSAT; при необходимости — обсудить сдачу недостающих анализов.

Врач: Ферритин и CRP доступны; интерпретируйте ферритин с учётом воспалительного контекста, клиники и лабораторных референсов. Рекомендуется оценить ретикулоциты, RDW, sTfR и TSAT; при необходимости — назначить недостающие исследования.

Условие: `{"presentAll": ["ferritin", "CRP"]}`.

### 13. vitamin_context (next_step)

Пациент: Результаты B12 и фолатов уже добавлены. Передайте врачу оба бланка и сведения о добавках, чтобы обсуждать их вместе.

Врач: Общий или активный B12 и фолаты представлены одновременно. Сопоставьте методы, единицы, даты и сведения о приёме добавок; наличие анализов не подтверждает дефицит.

Условие: `{"presentAll": ["folate"], "presentAny": ["vitamin_B12", "active_B12"]}`.

### 14. sparse (data_gap)

Пациент: Данных недостаточно для вывода о причинах и дефицитах. Пустые поля не считаются нормальными результатами; дополнительные исследования обсудите с врачом.

Врач: Малая панель ограничивает этиологический вывод. Пропуски не являются отрицательными результатами, а количество заполненных полей не является уверенностью модели.

Условие: `{"dataLevels": ["insufficient"]}`.

### 15. cbc_gap (data_gap)
