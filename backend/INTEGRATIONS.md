# Исследовательский API для клиник и лабораторий

**Новый API v1 принимает JSON и пакеты PDF и возвращает файлы PDF/JSON/ZIP для пациента и врача.** JSON → `POST /api/integration/v1/reports`; PDF → загрузка, обязательная проверка черновика, расчёт отчёта. Полный контракт, права `reports`/`pdf`, пример Python-клиента и границы безопасности — [11_LABORATORY_API.md](../docs/11_LABORATORY_API.md). Приведённый ниже старый `/api/integration/predict` сохранён для совместимости и возвращает только JSON; ключ без `--scope` имеет только это право.

Актуальная рабочая сборка от 2026-10-05: baseline_v1 + отдельный прогноз низкого ферритина v4. Case-головы сохранены; измеренный ферритин показывается как анализ. Для прогноза F18–44 нужен отдельный `pregnancyStatus` (`unknown`/`not_pregnant`/`pregnant`, по умолчанию `unknown`). Методика, ограничения, статусы и API — [docs/10_HYBRID_MODEL.md](../docs/10_HYBRID_MODEL.md).

Сейчас разрешены только синтетические или действительно обезличенные данные. Endpoint не предназначен для выдачи клинического отчёта реальному пациенту. Он не принимает ФИО/номера карт и не сохраняет запросы/ответы как медицинские записи. У лаборатории, браузера, reverse proxy и ОС могут существовать свои копии — их политика оформляется отдельно. Юридическая подготовка каждой стороны: `docs/legal/README.md`.

## Создание тестовой организации и ключа

Администратор выполняет команды в папке проекта; имя и контакт ниже вымышленные:

```sh
.venv/bin/python -m backend.integrations organization-create lab-demo --name "Вымышленная лаборатория" --contact "research@example.invalid"
.venv/bin/python -m backend.accounts create lab-demo.doctor --name "Тестовый врач" --organization lab-demo
.venv/bin/python -m backend.integrations key-create lab-demo --label "Синтетическая проверка" --days 30 --token-file /private/tmp/hema-lab-demo.key
.venv/bin/python -m backend.integrations key-list
```

На Windows замените интерпретатор на `.\.venv\Scripts\python.exe`, а token-file на новый файл в закрытой личной папке, например `"$env:USERPROFILE\hema-lab-demo.key"` в PowerShell. POSIX права нового файла 0600; Windows ACL нужно проверить отдельно. Администратор/владелец ОС остаются доверенными. Для production нужна защищённая система секретов, а не общий сетевой файл.

Если сервер запущен с другим `--data-dir`, указать тот же путь **перед** командой CLI: `python -m backend.integrations --data-dir data/local_v2 key-list`. CLI и сервер используют одну auth.sqlite3. organizationId уникален; это техническая запись, она не означает утверждённого оператора. Логины пока уникальны для всего экземпляра: используйте префикс организации. Пользователь не выбирает организацию при входе.

Ключ создаётся один раз в новом файле; существующий файл не перезаписывается. Plaintext не выводится в терминал и не хранится в базе. Срок по умолчанию 30 дней, допустимы 1–90 дней. База хранит SHA-256, организацию, метку, активность и срок. Не помещать ключ в URL, frontend, отчёт, исходники, git или обсуждение.

Отзыв по ID, показанному CLI:

```sh
.venv/bin/python -m backend.integrations key-revoke KEY_ID
```

Ротация: выдать новый, передать защищённым каналом, перевести интеграцию, отозвать старый. При утечке сначала отозвать, затем расследовать. Файл plaintext уничтожить отдельно по политике рабочего места.

## Контракт

POST `/api/integration/predict`, заголовки Content-Type: application/json и Authorization: Bearer [ключ]. Серверный API не требует браузерную cookie; не вызывайте его из публичной страницы с ключом. Тело:

```json
{
  "policyVersion": "research-privacy-2026-10-04-v1",
  "dataKind": "synthetic",
  "researchOnly": true,
  "audience": "patient",
  "inputs": {"age_years":42,"sex":"F","hemoglobin":108,"RBC":4,"MCV":78,"MCH":25,"RDW":17,"ferritin":9}
}
```

Актуальную policyVersion получить из GET `/api/privacy/status`. Второй допустимый dataKind — anonymized; он предполагает предварительно проверенное обезличивание. Входы/единицы/пропуски/минимальные панели те же, что в браузерном predict. Дополнительные поля отвергаются. В теле нельзя передать organisationId для подмены владельца, собственный verdict, patient_id, ФИО или произвольный текст.

Ответ: Hb/полнота/исследовательская модель/снимок draft-фраз, плюс `organizationId` из ключа, `stored:false`, `reportId:null`, `observationId:null`, `researchOnly:true`, `clinicalUseEnabled:false`. Числа `deficiencyScores`/`anemiaScores` — scores, не вероятность болезни. Нельзя затем читать этот результат через GET report: он не сохраняется. При недоступной модели 503; скрытой замены на демо нет.

Лимиты: JSON 128 КиБ, 60 запросов/минуту на ключ и 240 суммарно на процесс. 401 — нет/истёк/отозван ключ; 422 — схема/входы/вид данных; 429 — лимит; 503 — модель. Ограничения запросов в RAM сбрасываются при перезапуске; для сетевого сервиса нужны внешний rate limit и промышленная защита.

Полный schema JSON: `/openapi.json`. Swagger/Redoc с внешним CDN отключены, чтобы документация сервера не загружала сторонние скрипты. По умолчанию сервер слушает только 127.0.0.1. Открывать его в интернет без отдельного защищённого развёртывания нельзя считать готовым решением.
