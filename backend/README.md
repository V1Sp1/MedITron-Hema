# Локальный API Hema

Актуальная рабочая сборка от 2026-10-05: baseline_v1 + отдельный прогноз низкого ферритина v4. Case-головы сохранены; измеренный ферритин показывается как анализ. Для прогноза F18–44 нужен отдельный `pregnancyStatus` (`unknown`/`not_pregnant`/`pregnant`, по умолчанию `unknown`). Методика, ограничения, статусы и API — [docs/10_HYBRID_MODEL.md](../docs/10_HYBRID_MODEL.md).

Из корня проекта: `.venv/bin/python -m backend` (или `.venv/bin/hema-server`). Сайт и API работают в одном процессе FastAPI на http://127.0.0.1:8000/ . Интерактивная документация — http://127.0.0.1:8000/docs . Подготовленная `.venv` уже содержит зависимости. Новая установка: `python3 -m venv .venv`, затем `.venv/bin/python -m pip install -e '.[server,model,test]'`.

Параметры: `--port 8000`, `--data-dir data/local`, `--ocr auto|off|always`, `--freshness-policy policy.json`, `--phrase-file phrases.json`, `--model-bundle PATH` или `--no-model`. Сроки актуальности задаются явно в словаре `показатель → дни`; клинических сроков по умолчанию нет. CORS допускает локальные сайты на портах 8000 и 5173. Адрес bind всегда loopback.

## Вход для врача

Выбор «Я врач» открывает окно входа. База логинов и хешей паролей — `data/local/auth.sqlite3`. Создание записи: `.venv/bin/python -m backend.accounts create LOGIN --name "Имя"`; пароль запрашивается в терминале. Список: `.venv/bin/python -m backend.accounts list`. Отключение и сброс пароля — в [инструкции администратора](AUTH.md). Сеанс до 8 часов, есть кнопка выхода. Записей по умолчанию нет; первый аккаунт создаёт администратор.

## Наблюдение и проверка

Одна загрузка создаёт один UUID наблюдения независимо от дат. В `measurements` остаются все кандидаты с источником, страницей, строкой, единицами, датой и ошибками. `inputs` — черновик: повторы, границы `<`/`>`, неподдержанные единицы, будущие/устаревшие даты не подставляются автоматически. Пол/возраст вводятся пользователем.

Пересчёт по `data/feature_dictionary.json` допускается между совместимыми единицами: например Hb g/dL→g/L, ферритин ng/mL→µg/L, MMA nmol/L→µmol/L. Нет догадок по числу и конверсий массы в молярную концентрацию. Исходное число/единица сохраняются рядом с пересчитанными. CLI парсера сохраняет исходные единицы; этот слой нормализации добавлен в API.

Первый клик после выбора PDF открывает форму. Повторный клик подтверждает значения и запускает расчёт: `reviewedObservation: true`, `observationId`, `observationRevision`. Подтверждение увеличивает ревизию; несовпадающая версия даёт 409. Исправления хранятся отдельно от извлечённых строк. Это подтверждение входной формы, а не верификация каждого кандидата PDF. Детальный выбор источников/измерений в интерфейсе остаётся следующей доработкой.

## Хранение и ограничения

Новые медицинские записи/исходные PDF — SQLite :memory: до часа с research-подтверждения, без продления. Очистка/DELETE/logout/перезапуск удаляют их, observation DELETE каскадно удаляет PDF и связанные reports. auth.sqlite3 хранит учётные записи/организации/хеши ключей отдельно. Историческая hema.sqlite3 не открывается, не уничтожается автоматически. Все records требуют своей research-cookie; doctor-объекты дополнительно своей учётной записи. Реальные идентифицируемые данные и клиническое применение пока не допускаются.

Лимиты: 10 файлов, 20 МиБ на файл, 60 МиБ PDF на пакет, 100 страниц на документ; до 61 МиБ на HTTP-запрос с multipart-обрамлением. Один пакет одновременно, следующий получает 429. Парсер работает в отдельном процессе: через 180 секунд группа процессов завершается, возвращается 504. Это ограничение времени, не полноценная изоляция или лимит памяти. Неудачная загрузка удаляет свои временно сохранённые файлы. Частично распознанный пакет возвращает предупреждения; пакет без кандидатов — 422.

Apple Vision OCR запускается локально на macOS. Сканы требуют ручной проверки: публичный Lab4U распознаётся неполно, включая Hb. Интеграция не повышает измеренное качество OCR.

## Модель и клинические фразы

По умолчанию загружается `experiments/baseline_v1/models/selected.joblib`: лучшие кандидаты первой серии, выбранные по development CV до holdout. Весами служат уже обученные модели; повторное обучение при запуске не требуется. Анемия остаётся строго Hb <120 для F и <130 для M по кейсу. Для каждой из семи целей загружаются основной кандидат и отдельный кандидат для ОАК. Только показатели ОАК → `modelPanel: "cbc"`; любой дополнительный лабораторный показатель → `"primary"`. Это маршрутизация первой исследовательской версии, не клинически валидированный выбор панели.

Нужны зависимости `.[server,model]` или `ml_baselines/requirements.txt`. Файл весов исключён из Git: для другого компьютера его нужно перенести отдельно или воспроизвести обучение по `ml_baselines/README.md`. Схема 37 входов, версии словаря, классы и оба режима проверяются при запуске. Версия отчёта `hema-baseline-v1-<12 символов SHA-256 весов>`. Веса загружаются один раз, вычисления выполняются локально, пропуски остаются `null` во входах и обрабатываются сохранёнными preprocessing/models.

`GET /api/models/status` возвращает `ready/unavailable/disabled`, выбранные модели, версию и `calibrated: false`. При ошибке загрузки health показывает `degraded`, прогноз возвращает 503; скрытой подмены правилом или демо нет. `--model-bundle PATH` задаёт доверенный локальный joblib (не загружайте чужую сериализацию), `--no-model` явно включает прежний режим правила Hb.

Отчёт содержит `modelVerdict`, `modelDecisionState`, `prediction`, оценки пяти дефицитов и 12 классов (последние отображаются только при анемии), выбранные кандидаты и версию весов. Все числа исследовательские и не откалиброваны; низкая оценка не исключает дефицит. Порог бинарных решений 0,5 соответствует эксперименту. Дополнительная политика интерфейса воздерживается от вывода при максимальной оценке класса <0,5, несогласованности класса с Hb/бинарными целями и попытке исключить причины по ограниченной панели; этот порог не проверенная мера клинической уверенности. Ниже 5 лабораторных значений причинный вердикт подавлен (`suppressed_sparse`), числовые оценки не выдаются. Пол, возраст и Hb для маршрута predict остаются обязательными; предварительная проверка полноты допускает их отсутствие.

По умолчанию подключены два пула по 20 фраз: `data/recommendations_patient.json` и `data/recommendations_doctor.json`, версия `phrases-draft-1.2`, статус `draft`. [Полные тексты, правила и форматы](RECOMMENDATIONS.md). Отдельно возвращаются выводы, следующие шаги и блок недостатка данных. Ниже 5 лабораторных значений/при отсутствии основных входов специфические сообщения о причине подавляются; это настраиваемая политика прототипа, не валидированная уверенность модели. Фразы не утверждены клинически, предупреждение сохраняется в отчёте. При настоящем расчёте специфические фразы выбираются по структурированному вердикту модели; неопределённые, противоречивые и слишком скудные результаты подавляют эти ветки. Preview остаётся явно обозначенной симуляцией и не сохраняет отчёт. Локальный JSON должен содержать `version`, `reviewed: true`, `items`: уникальный строковый `id`, непустой `text`, `audience` (`doctor`, `patient`, `both`), `when` (объект, допускающий булевый `anemia`). Файл должен быть согласован командой; маркер reviewed сам по себе не доказывает клиническую проверку. Ошибка заданного файла возвращает 503. Параметр --phrase-file заменяет только следующие шаги; черновые выводы/полнота и их предупреждение сохраняются.

Следующие этапы: независимая проверка и калибровка модели, медицинское согласование черновых фраз, выбор источника повторных измерений и политика давности. Пропуски не заполняются нулями.

## Сравнение исследовательского кандидата v2

Для калиброванного кандидата третьей серии см. раздел ниже; v1 и v2 сами по себе не откалиброваны.

Рабочая версия по умолчанию — baseline_v1. После новой серии обучения robust_v2 остался кандидатом: повышение устойчивости к пропускам сопровождалось регрессиями, поэтому замена рабочего набора не выполнена. Его можно запустить отдельно на 8001 с `--model-bundle experiments/robust_v2/models/selected.joblib --data-dir data/local_v2`. Авторизация врача действует и в этом экземпляре; его база учётных записей отдельная. `/api/models/status` и каждый отчёт указывают `modelFamily` и семейство в `modelVersion`; `classScoresConditionedOnHb` показывает согласование оценок классов с известным статусом Hb в соответствующей ветке. Оценки по-прежнему не откалиброваны. Полное сравнение — `experiments/robust_v2/REPORT.md`.

## Калибровка calibrated_v3

```sh
.venv/bin/python -m backend --port 8002 --data-dir data/local_v3 --model-bundle experiments/calibrated_v3/models/selected.joblib
```

Подключает сохранённые v1 веса и калибраторы, обученные на development OOF с вложенной проверкой. Калибровка выбрана для 10 из 14 задач/панелей; четыре остались исходными. Семейство `calibrated_v3`, версия `hema-calibrated-v3-2e16ec3c201c`. В `/api/models/status` и отчёте: `calibrationApplied=true`, `calibration.status=partial`, `calibration.methods`, `appliedHeads`, `retainedRawHeads`, `clinicalValidated=false`, `independentValidation=false`. `calibrated` означает преобразование **всех** голов (в статусе — обеих панелей, в прогнозе — активной панели), поэтому в этом наборе false. `scoreMeaning=partially_calibrated_research_score`; никакой клинической вероятности этим не заявлено. Проверка SHA-256 до десериализации действует и для v3.

Политики полноты, согласованности, отказа, фраз и исследовательского доступа действуют как для v1. Более резкие оценки меняют долю причинных выводов при прежнем пороге 0,5: на повторном holdout 56,0%→68,5%, совпадение выданных классов с CSV 96,8%→93,9%. Поэтому v3 остаётся отдельным кандидатом; default v1 сохранён. Сам holdout уже использован и не является новой независимой проверкой. Внешнее дообучение не прошло критерии улучшения и в этот bundle не включено. Полный отчёт — `experiments/calibrated_v3/REPORT.md`.

## Исправленный контур

POST /api/privacy/acknowledge — researchOnly/synthetic|anonymized/policyVersion, не юридическое согласие. DELETE /api/privacy/session очищает текущий medical-сеанс. JSON limit 128 КиБ, Store 128 МиБ/1000 объектов, private staging/worker limits, CSP/no-store, предварительная SHA-256-проверка joblib. OpenAPI — /openapi.json, внешние Swagger/Redoc отключены. Лабораторный stateless endpoint и отзываемые ключи — INTEGRATIONS.md; подробные исправления — docs/09_SECURITY_REMEDIATION.md. Установка использует constraints requirements-runtime.txt.
