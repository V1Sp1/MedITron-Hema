- Во всём XLSX нет пустых ячеек, пустых строковых значений, нечисловых значений в числовых столбцах или бесконечностей.

## 3. Какие исходные метки действительно есть

### Многоклассовая метка и четыре её индикатора

| All_Class | Значение | Строк | Положительный исходный флаг |
|---:|---|---:|---|
| 0 | Без анемии | 9 747 | Все четыре флага равны 0 |
| 1 | HGB-анемия | 1 019 | HGB_Anemia_Class |
| 2 | Железодефицитная анемия | 4 182 | Iron_anemia_Class |
| 3 | Фолатодефицитная анемия | 153 | Folate_anemia_class |
| 4 | B12-дефицитная анемия | 199 | B12_Anemia_class |

Все четыре флага имеют только значения 0/1 и **точно равны индикаторам соответствующего All_Class**. Во всех строках сумма флагов равна 0 для класса 0 и 1 для остальных классов. Независимой многометочной разметки дефицитов в файле нет.

В частности, HGB_Anemia_Class — не наша общая `anemia`: если принять его за общий флаг, ошибочно потеряем 4 534 анемичных записи других классов. Общий исходный флаг анемии получается как `All_Class != 0` или OR четырёх исходных индикаторов: 5 553 положительных и 9 747 отрицательных.

### Обнаруженное точное воспроизведение классов

При интерпретации GENDER=0 как F и GENDER=1 как M зададим:

```text
A = Hb <120 g/L для F или Hb <130 g/L для M
I = ferritin <15 µg/L OR TSAT <20%
F = serum_folate <4 ng/mL
B = total_B12 <200 pg/mL  # предполагаемая единица источника

if not A:          All_Class = 0
elif I:            All_Class = 2
elif F:            All_Class = 3
elif B:            All_Class = 4
else:              All_Class = 1
```

Эта программа воспроизводит **15 300 из 15 300 меток**, без расхождений. Иначе говоря, в этом файле выполняются:

```text
Iron_anemia_Class   = A AND I
Folate_anemia_class = A AND NOT I AND F
B12_Anemia_class    = A AND NOT I AND NOT F AND B
HGB_Anemia_Class    = A AND NOT I AND NOT F AND NOT B
```

Это установлено анализом всей таблицы. Это не опубликованный код авторов и не доказательство того, каким способом они изначально поставили диагнозы. Не называть этот результат клинической точностью или качеством обученной модели. Классы здесь содержат сильную зависимость от правил по тем же входным показателям.

Порядок условий скрывает сочетания. У класса IDA 710 записей с B12<200 и 280 с фолатом<4; у фолатодефицитного класса 26 с B12<200. Более раннее правило определяет единственный класс, а остальные индикаторы остаются нулевыми.

У 2 013 из 4 182 IDA-записей ферритин ≥15, но TSAT<20. Низкая TSAT может отражать ограничение доступности железа, в том числе на фоне воспаления. Без CRP и других данных нельзя считать все эти записи доказанным абсолютным железодефицитом в смысле нашей разметки.

Класс 0 означает только отсутствие анемии. В нём 5 862 записи удовлетворяют хотя бы одному из I/B/F; 986 — как минимум двум. По более строгим низким сигналам ferritin<15, B12<180, folate<3 таких записей 2 699, в том числе 230 с несколькими низкими показателями. Эти числа предполагают оговорённые единицы B12/TSAT и являются результатами правил, не новыми врачебными диагнозами.

Пороги не подбирались для максимизации совпадения с кейсом. Для каждой проверки взяты только записи, где измерены необходимые показатели; для железного OR требуются оба анализа, чтобы корректно определить отрицательный результат. Пропуски не заменены нормальными значениями.

## 5. Приведение единиц

Созданы две копии в схеме исходного CSV: 48 столбцов в том же порядке, отсутствующие данные — пустые ячейки, ID — техническая ссылка на строку XLSX. Исходники не изменены. Целевые столбцы в этих копиях содержат только осторожный прямой перенос исходных меток, описанный ниже.

### Подтверждённые преобразования

Документация — [таблица 1 исследования на том же файле](https://onlinelibrary.wiley.com/doi/10.1111/exsy.13528); численные границы таблицы совпадают с XLSX. В ней есть ошибки для части других полей, поэтому статус происхождения единиц сохраняется.

| Источник | Наш столбец | Операция | Наша единица |
|---|---|---|---|
| HGB | hemoglobin | ×10 | g/L |
| HCT | hematocrit | ×1 | % |
| MCV | MCV | ×1 | fL |
| MCH | MCH | ×1 | pg |
| MCHC | MCHC | ×10 | g/L |
| RDW | RDW | ×1 | % |
| PLT | platelets | ×1, K/µL численно равно 10⁹/L | 10^9/L |
| FERRITTE | ferritin | ×1, ng/mL численно равно µg/L | µg/L |
| SD | serum_iron | ×0,1791, µg/dL → µmol/L | µmol/L |
| FOLATE | folate | ×1 | ng/mL |

Эти 10 показателей заполнены в `case_units_verified_source_partial.csv`. Пол, RBC, WBC, B12, TIBC/TSAT и UIBC в этом варианте неизвестны; это сознательное сохранение неопределённости, а не потеря исходных значений. Raw XLSX сохранён.

### Рабочие предположения для более полного варианта

В `case_units_candidate_source_partial.csv` дополнительно записаны:

1. `sex`: GENDER 0→F, 1→M. Основания — опубликованные числа женщин/мужчин и полное совпадение правила Hb с All_Class. Индивидуальных демографических данных для дополнительной проверки нет.
2. `RBC`: считаем исходный масштаб 10¹²/L, сохраняем число. Опубликованное 10³/mL противоречит обычному смыслу RBC и соотношениям CBC. Предположение подтверждается согласованностью HCT≈RBC×MCV/10 и MCH≈Hb[g/L]/RBC.
3. `WBC`: считаем 10⁹/L, сохраняем число. Напечатанное 10³/mL предположительно является ошибкой вместо 10³/µL, но отдельного подтверждения автора нет.
4. `vitamin_B12`: считаем pg/mL, сохраняем число. В статье указано ng/mL. Распределение и класс B12<200 поддерживают рабочую гипотезу pg/mL; они не являются независимым документальным подтверждением. **Не умножать на 1000 автоматически.**
5. `TIBC`: считаем SDTSD общей железосвязывающей способностью в µg/dL, умножаем на 0,1791.
6. `TSAT`: считаем TSD процентом, сохраняем число. Во всех строках TSD=100×SD/SDTSD с максимальной ошибкой 6,4×10⁻¹⁴. Название и единица TSD в документации противоречивы.
7. `UIBC`: вычисляем `TIBC−serum_iron`. Не выдаём расчёт за исходное отдельное измерение; он зависит от правильности пунктов 5–6 и предположения о согласованной паре исследований.

Коэффициенты не являются min-max стандартизацией. Числа в скачанном файле представлены в исходных лабораторных масштабах, а не в диапазоне 0–1. Статистическое масштабирование/импутация здесь не выполнялись.

## 6. Аномалии и контроль качества

### Формальная корректность

Домены All_Class=0..4, исходных флагов=0/1 и GENDER=0/1 соблюдены. HCT и предполагаемый TSAT не выходят за 0–100%; serum iron не превышает предполагаемый TIBC. Нечисловых, NaN и бесконечных значений нет. Проверки алгебраических соотношений выявили максимальные отклонения:

- MCH от 10×Hb[g/dL]/RBC: 0,183 pg.
- MCHC от 100×Hb[g/dL]/HCT[%]: 1,001 g/dL.
- HCT от RBC×MCV/10: 0,133 процентного пункта.
- TSD от 100×SD/SDTSD: 6,4×10⁻¹⁴.

Согласованность формул не гарантирует правильность измерений: ошибочные исходные Hb/RBC/HCT могут дать столь же согласованные расчётные индексы.

## 7. Подробный метод формирования наших меток

### Общие требования ко всем вариантам

1. Сохранить raw XLSX и его хеш, версии источника, словаря единиц и правил. Сверить названия/типы столбцов и целевые индикаторы.
2. Создать технический ID из номера строки Excel. Это ссылка на запись, не установленный patient ID. Сохранить raw-feature hash как группу одинаковых записей.
3. Разделить признаки, исходные цели, QC и новую разметку. Ни All_Class, ни четыре исходных флага, ни технические ID/происхождение не становятся признаками модели.
4. Выполнить документированные преобразования. Для остальных полей использовать только вариант с явными предположениями. Не заполнять возраст, CRP, B6, медь или другие отсутствующие показатели.
5. Для каждой цели сохранять значение, известность и происхождение. Пустая CSV-ячейка означает неизвестно (`null`), никогда не отрицательный результат.
6. Сохранять исходную метку рядом с правилами. Низкий показатель и исходный класс могут содержать разную информацию; смена категории не уничтожает исходный диагноз.
7. Поставить QC-флаги; не выполнять универсальное отбрасывание статистических выбросов. Дедупликацию делать до разбиений, с сохранением соответствия исходным строкам.

Пороговые сравнения строгие: Hb ровно 120 у F/130 у M не даёт анемию по правилу кейса; ferritin ровно 15, B12 ровно 180 и folate ровно 3 не дают соответствующий низкий сигнал B. В C железное правило при ferritin=15 и TSAT=20 ложно; B12=200 и folate=4 также не дают положительный прокси. Это границы вычислительных правил, не доказательство здоровья на пограничном результате.

В проверенном источнике все необходимые значения присутствуют. Если переносить программу на файл с пропусками, сравнение отсутствующего анализа с порогом не должно превращать неизвестность в 0. Для OR железа достаточно одного известного положительного условия, чтобы получить 1; 0 по правилу C допустим только когда оба анализа известны и оба условия ложны; иначе результат null. Для Hb нужны гемоглобин и допустимый код пола, иначе anemia=null. Для B достаточно исходной положительной метки или известного низкого показателя, иначе target=null. Неподтверждённая единица означает отдельную неопределённость даже при наличии числа. Текущий скрипт проверяет отсутствие NaN/бесконечностей в исходном XLSX и предназначен именно для зафиксированной версии, а не для автоматического импорта произвольных таблиц.

### Вариант A — прямые частичные метки источника

Файл `labels_source_partial.csv`; именно этот вариант включён в нормализованные копии.

```text
anemia = int(All_Class != 0)

iron_deficiency   = 1 при All_Class=2, иначе null
B12_deficiency    = 1 при All_Class=4, иначе null
folate_deficiency = 1 при All_Class=3, иначе null

B6_deficiency = copper_deficiency = inflammation_anemia = null
mixed_deficiency = null
anemia_class = deficiency_cause = null
```

Статус анемии совпадает с кейсовым правилом по Hb при принятом кодировании пола. Положительные дефицитные метки имеют происхождение `source_class`; эквивалентность клинических критериев источника и кейса ещё не подтверждена. Для IDA особенно важны 2 013 записей с ферритином ≥15 и низкой TSAT.

Нули one-hot не копируются как отрицательные дефициты. Вариант даёт 4 182 положительных железных, 199 B12 и 153 фолатных метки; остальные состояния неизвестны. Гарантированного точного одиночного класса под наши 12 категорий из этой информации получить нельзя.

### Вариант B — дополнение положительными низкими сигналами

Файл `labels_source_plus_low_candidates.csv`. Используются прямые метки A и независимо вычисляются:

```text
iron_low   = ferritin <15 µg/L
B12_low    = total_B12 <180 pg/mL
folate_low = serum_folate <3 ng/mL

target = 1, если положителен соответствующий исходный класс OR low-сигнал
target = null в остальных строках
```

Сравнения строгие: ровно 15/180/3 не относится к низкому сигналу. B12 требует принятия предположения об единице. Пустое/нечисловое/отрицательное или отмеченное как ошибочное значение в будущих версиях должно давать неизвестный сигнал, а не отрицание. В текущем файле таких значений в нужных столбцах нет.

Основания:

- [ВОЗ, ферритин](https://www.who.int/publications/i/item/9789240000124): низкий ферритин — показатель сниженных запасов; порог и интерпретация зависят от популяции и воспаления. Порог 15 выбран здесь как консервативный положительный сигнал. Отсутствие CRP не позволяет присвоить отрицательный железодефицит по нормальному/высокому ферритину или применять коррекцию воспаления.
- [NICE NG239, таблица 1](https://www.nice.org.uk/guidance/ng239/chapter/Recommendations): <180 ng/L, численно равных pg/mL, относится к определённой низкой области; 180–350 — неопределённая область. Более высокий B12 не превращается здесь в подтверждённую отрицательную метку: неизвестны приём препаратов, симптомы и функциональные маркеры.
- [ВОЗ, сывороточные фолаты](https://extranet.who.int/indcat/TemplateView.aspx?id=32): <3 ng/mL — низкая область, связанная с гематологическим критерием; <4 ng/mL используется для иной метаболической оценки. Разовые сывороточные фолаты отражают недавний статус/потребление и не доказывают самостоятельно этиологию анемии.

Далее подсчитывается количество положительных iron/B12/folate:

```text
если положительных >=2: mixed_deficiency=1 (кандидат)
иначе: mixed_deficiency=null
```

`mixed_deficiency=0` не ставится: B6/медь неизвестны и могут образовать не наблюдаемое здесь сочетание. Сочетание метки источника и нового биомаркерного сигнала сохраняется как комбинация доказательств разного типа; кандидат не объявляется подтверждённым смешанным диагнозом.

Всего: iron 6 011, B12 1 644, folate 396 положительных кандидатов; mixed 797, из них 567 при анемии и 230 без анемии. Только по низким сигналам без добавления исходных классов сочетания есть у 545 записей: 315 с анемией и 230 без неё. Не смешивать эти два подсчёта.

### Вариант C — независимые прокси по восстановленным правилам источника

Файл `labels_source_rules_weak.csv`. Он нужен для исследования зависимости от метода разметки и сопоставления с B, а не для автоматического принятия медицинских диагнозов.

```text
anemia = A
iron_deficiency_proxy   = int(ferritin<15 OR TSAT<20)
B12_deficiency_proxy    = int(B12<200)
folate_deficiency_proxy = int(folate<4)
```

В CSV прокси записаны под именами наших трёх бинарных целей, но происхождение явно обозначено в `rules.json`/`label_origins.csv`, статус — weak. Ноль означает «правило не выполнено», а не клинически доказанное отсутствие дефицита. Это экспериментальный профиль, не вариант A. Все B6/медь/воспаление неизвестны; mixed ставится только положительным при двух или более положительных прокси, иначе неизвестен.

В отличие от All_Class, здесь не применяется приоритет железо→фолат→B12 и не прекращается анализ при нормальном Hb. Поэтому появляются скрытые и смешанные состояния. Iron — 9 216, B12 — 2 342, folate — 882 положительных прокси; mixed — 1 944, из них 958 с анемией и 986 без. Эти количества чувствительны к более широким порогам и ошибкам единиц.

### Как предлагается назначать многоклассовую метку в B/C

В A все итоговые классы остаются неизвестными. В B/C `anemia_class` содержит **кандидатов** следующих семи наших классов; общий статус и маска запрещают считать их уже утверждённой разметкой.

```text
положителен только iron:
    при anemia=1 -> iron_deficiency_anemia
    при anemia=0 -> latent_deficiency  # узкая семантика текущего CSV

положителен только B12:
    при anemia=1 -> B12_deficiency_anemia
    при anemia=0 -> B12_deficiency_no_anemia

положителен только folate:
    при anemia=1 -> folate_deficiency_anemia
    при anemia=0 -> folate_deficiency_no_anemia

положительны >=2 из трёх:
    mixed_deficiency=1
    при anemia=1 -> anemia_class=mixed_deficiency
    при anemia=0 -> anemia_class=null

нет положительных результатов:
    anemia_class=null
```

«Только» здесь означает только среди доступных/принятых трёх показателей, а не доказанное отсутствие других дефицитов. В B даже остальные из трёх могут быть неизвестны. Поэтому одиночные классы — предложения, которым требуется дополнительная проверка; также B12/фолатный низкий показатель не доказывает причинную связь с анемией.

Не формируются `no_anemia_no_deficiency`, `anemia_other`, `B6_deficiency`, `copper_deficiency`, `inflammation_anemia`: для их семантики не хватает исследований и диагностики. Исходный HGB-класс не доказывает исключение B6, меди, воспаления и иных причин. При смешанных состояниях без анемии сохраняются бинарные кандидаты; итоговая категория не придумана, поскольку в текущем CSV такие смешанные примеры не представлены.

`deficiency_cause` в B/C показывает **известную комбинацию среди трёх**, а не исчерпывающую причину: iron_deficiency/B12_deficiency/folate_deficiency, iron_B12, iron_folate, B12_folate, iron_B12_folate. Последнее значение отсутствует в текущем CSV; оно появляется у 21 кандидата B и 100 кандидатов C, поэтому нельзя без расширения словаря подавать его в обученную на старом наборе классификацию причины. В A причина остаётся неизвестной. Не назначается `none` или `undetermined` по неполной панели.

## 8. Как использовать результаты в обучении

Рекомендуемый старт — сравнение обучения только на кейсе с добавлением прямых частичных меток A, затем отдельный эксперимент с положительными кандидатами B. C — проверка чувствительности к методу разметки, а не основной медицинский эталон.

- Для бинарной задачи использовать masked loss: неизвестный target не участвует в сумме. Обычная замена пустот на 0 разрушит смысл разметки. На одних внешних положительных метках без отрицательных примеров полноценный бинарный классификатор не обучается; нужны известные отрицательные случаи из кейса/других проверенных источников или отдельный подход к positive-unlabeled данным.
- Не объединять 15 300 внешних и 840 кейсовых строк без контроля вклада источника. Подбирать веса/сэмплинг и способ работы с неполными панелями внутри обучения, сравнивать результат на отдельной проверке кейса.
- Группировать одинаковые raw-feature vectors при разделении. Для первого варианта можно использовать копию с 15 212 строками после дедупликации; QC-флаги присоединяются из `row_audit.csv` по техническому ID. Копия не становится автоматически пригодной для обучения. Сведения о повторных пациентах/визитах отсутствуют.
- Запись 6211 оставить на отдельном разборе. Остальные 67 отмеченных экстремальных строк анализировать индивидуально; автоматическое удаление патологических случаев меняет целевую популяцию. Если вводится научившееся по данным преобразование, обучать его только на train.
- Сравнить модель на общем наборе доступных признаков с моделью с пропусками. Источник и доступность панели не должны подменять распознавание дефицита.
- Готовые source-rule/biomarker-rule метки вычисляются по тем же анализам, которые подаются на вход. Высокая оценка на них измеряет воспроизведение правил; клиническую точность оценивать на независимо поставленных метках. Найденные по всей таблице правила не считать независимым тестированием.
- Анемию при наличии Hb и данных о поле определять прозрачным правилом кейса; ML для воспроизведения этого порога сам по себе не добавляет диагностической информации.
- Нельзя утверждать, что этот набор обучит выявлять B6/медь/воспаление или отрицать все дефициты у здоровых: соответствующих измерений/меток нет. Возраст не восстанавливать по диагнозу.
